# ADR-0002：可选个人多设备复制，预留团队空间

[English](0002-optional-cloud-replication.md) | [简体中文](0002-optional-cloud-replication.zh-CN.md)

日期：2026-10-29。状态：**已确认设计预留，未实现**。
用户选择先个人多设备、未来团队协作；本轮只修改文档，不创建服务工程或运行云同步。

## 决定

- 本地优先和 Rust Core 基线不变。无需账号/云连接即可使用本地任务；
  UI/四端插件访问各自本机 Core，每台设备的 profile 单写入者不变。
- 云阶段在同仓 services/reed-server 建独立 Rust 服务工程/workspace/锁文件，
  单独构建、存储、部署和升级；本地包不含云依赖。
  现有三个 crate 内预留领域规则、版本化复制契约及 runtime 复制适配。
- 复制空间和设备/副本身份与 profile 分开。白名单业务数据及选择附件复制，
  共享接纳版本与本地 revision 分开，不同步 SQLite/WAL、凭据、控制能力和可消费操作队列。
- 共享历史与当前业务适用性分开；离线决定保留，冲突显式处理，不按时间戳合并验收。
  接收副本不重放 Agent、验收或云效操作。
- 原生执行所属设备及云效规范对象写入所属设备单独确认；
  未决影响未处置不自动交接，不以租约过期夺权。
- 先 C1 数据复制；新共享原生派发/来源写入的手动与规则入口均等 C2 验收，既有执行核查/停止及非共享任务不受此限制；C3 扩展团队成员/权限。
  本地 M1–M8 只做边界预留，P8 反向集成与云路线独立。

## 取舍与非目标

单仓可复用纯业务规则和契约，独立 workspace 防止云依赖影响 Core-only；
代价是维护两类存储/协议兼容、身份/冲突、恢复与设备交接。
个人复制不承诺跨机实时一致或远端副作用 exactly-once；
需要共享协调的新动作在依据/占用未确认时等待，但本地保存和既有执行不因此中断。
不提前建设 CRDT、全事件溯源、通用调度或团队权限平台。

规范细节与数据白名单只维护于[复制专题](../architecture/replication.md)，
阶段和云验收只维护于[计划](../engineering/implementation-plan.zh-CN.md)/
[RF 主清单](../engineering/failure-acceptance.md)。当前三 crate/本地基础验证记录不因本 ADR 改写。
