# 开发规范与 Agent 工作方式

[English](standards.md) | [简体中文](standards.zh-CN.md)

本规范供开发者和 Code Agent 接手 Reed 时使用，适用于当前 Rust／React／Tauri 正式工程。
对标项目的源码事实、适用范围及取舍见[Codex CLI／Tauri 工程实践记录](../references/engineering-practices.md)，
不将历史原型或外部项目的全部做法直接升级为本项目规则。

## 规则归属与当前阶段

- [AGENTS.md](../../AGENTS.md) 是 Agent 入口与仓库保护边界。
- [架构总览](../architecture/overview.zh-CN.md) 负责模块职责及依赖方向；所属 `BOUNDARY.md` 说明局部职责和实现状态。
- [领域模型](../product/domain-model.md) 等产品文档负责业务语义；本文件负责开发方式，不另设业务模型。
- [开发指南](development.zh-CN.md) 负责工具链、实际命令和产物；[前端指南](frontend.zh-CN.md) 负责当前共享 UI 的具体组织。
- 用户任务决定授权范围。已授权范围内的常规细节自行推进，不重复询问；未覆盖的产品决策、边界变化或不可逆操作，
  在实施相关步骤前说明并取得决定。Git／发布和外部写入按本次会话授权执行，文档或 Skill 不能制造权限。

当前正式前端显式使用模拟适配。Core 业务存储、正式认证业务 API、真实宿主与连接器执行尚未接入。
只实现本次分配的部分，区分源码事实、设计目标和实际运行证据。

## 开始工作前

核对实际仓库根、分支、HEAD、工作区和未跟踪文件；读取根规则、贡献指南、docs 导航及所属边界说明。
沿实际调用链查看实现、消费者和已有测试，再说明与任务相称的计划：预期行为、模块落点、失败情况和验证方式。
分析／评审请求保持只读，除非同时获得实现授权。

保留其他任务已有改动。并行任务需要文件归属不重叠或明确协调；独立 worktree 不会隔离共享数据库、端口和远端资源。
不自动 stash、reset 或清理其他工作。

## 模块与依赖约束

| 所属模块 | 职责与边界 |
| --- | --- |
| `crates/reed-core` | 纯领域／应用规则与端口；不实现数据库、网络、GUI 或宿主 SDK 适配 |
| `crates/reed-protocol` | 通信类型与兼容规则；不包含数据库实体或应用决策 |
| `crates/reed-runtime` | 独立服务及基础设施装配；不依赖窗口或 React |
| `packages/client` | 宿主无关传输与生成类型；不依赖 UI、应用壳或原生 SDK |
| `packages/ui` | 共享产品呈现，可消费 client；不导入应用壳或原生 SDK |
| `apps/web`、`apps/desktop` | 装配共享 UI/client 并注入允许能力；两种壳不互相导入实现 |
| `packages/ui/src/mock` | 独立模拟适配、样例及模拟规则；不是 Core 契约或正式持久化 |
| `tooling`、根 `tests` | 工程检查及其测试，不承接产品服务或用户运行数据 |

工作台及 UI 主入口不能经中间模块／再导出间接取得 mock 实现。壳可以显式选择 `@reed/ui/mock`。
JS/TS 产品源码不能导入测试文件或专用测试框架；测试可以导入实现。类型导入同样涉及模块归属。

Rust 清单及两个 Cargo workspace 保持 Core 构建独立于 GUI。当前骨架检查器禁止 reed-core 的全部声明依赖，
protocol 也只有有限允许集。真实领域实现需要新增纯依赖时，评审其归属，并有意调整门禁和反例；不通过别名绕过或静默放宽。

只在实际依赖、构建或运行边界需要时增加 crate/package。外部 Connector 保持可替换；宿主适配属于 ai-code，
通用 Agent Bridge 属于 ai-mcp。跨仓变更须读取该仓规则并具备相应授权。

## 代码组织与语言实践

- **Rust：**使用已固定工具链、rustfmt 和相应 Clippy 检查。可执行入口保持薄，库和端口暴露最小必要接口；
  预期失败返回结构化错误。阻塞文件／数据库操作与异步执行线程隔离，队列、读取和输出有界。
- **TypeScript／React：**新模块和新边界使用严格 TS／TSX。Hook 在顶层调用，渲染保持纯，props/state 不直接修改；
  实际副作用进入事件处理、effect 或注入适配，并释放订阅、计时器等资源。迁入 JSX 保留明确的 `allowJs`／`checkJs: false` 范围。
- **内部 UI 接口：**生产者和消费者共同维护明确接口，优先按功能收窄能力和视图投影；不继续用各组件自行断言未类型化服务替代共享约束。
  既有同步／unknown 模拟端口属于迁移债，不是 Core API。
- **代码落点：**页面负责组合功能，复用表单不反向依赖页面模块。任务、关系、连接器自己的组件与协调逻辑按功能就近维护；
  有实际复用再抽公共组件。需要时在现有包内建立功能目录，不创建空骨架或按对象拆新包，也不借无关任务搬迁所有旧平铺文件。
- **Python／工具：**采用 PEP 8 的命名、缩进习惯，脚本尽量小、确定、使用标准库；门禁失败返回非零状态。
  Python／Node 工具不能成为 Core 的运行依赖。
- **文案／样式：**固定 UI 文案归 `workbench/locales`，用户标题和正文保留原数据；公开文档双语一致。
  复用既有主题变量、组件和样式归属；有预览条件时核对受影响的双语、主题及窄窗口，不在整理代码时顺带重做视觉。

语言机制和成熟工程的做法是依据，不意味着上游每条约定都适合 Reed。
例如，不照搬 Codex 的 Bazel 基础设施，也不照搬 Tauri 的发行或社区治理政策。

## TDD 与测试组织

TDD 是 **Reed 的开发方式**：行为变化先写最小可观察失败用例，运行确认预期断言失败，再最小实现、绿色下整理。
缺工具、缺依赖、语法错误或环境阻断不算 RED。不为通过而削弱断言，不写镜像实现的测试、空测试组或用数量冒充覆盖。
纯重构先有既有绿色基线；文档／纯格式变更使用结构检查及已有相关测试，不人为制造应用测试失败。

| 语言／层次 | Reed 的组织方式 |
| --- | --- |
| Rust 私有单元测试 | 正文默认放独立 `foo_tests.rs` 模块文件；实现文件仅保留 `#[cfg(test)]`／`#[path]` 子模块声明，保留私有访问，不内嵌测试正文 |
| Rust 公开 API 集成测试 | 放所属 crate 的 `tests/`，公共辅助代码放子模块；不为搬测试扩大生产 API |
| TS／React／Vitest | 沿用所属模块的 `tests/**/*.test.ts(x)`，产品实现文件不内嵌测试 |
| Node 模拟规则测试 | 放 `packages/ui/tests/mocks/*.test.mjs`，与 `src/mock` 分开 |
| Python 工程检查 | 根 `tests/test_*.py`，通过 unittest 发现；产品测试仍随所属产品模块 |

物理文件、Rust 模块和独立 Cargo/npm 包是不同边界。Reed 默认选择单测正文独立，不在产品实现文件中新增测试正文；
Rust 测试模块保持条件编译，不为迁移而公开私有函数，也不为每个组件另建测试 workspace 或空测试目录。
对标记录保留上游两种 Rust 布局的事实；正文独立是 Reed 的项目选择，不表示另一种写法违反 Rust。
有意例外按下文规则变更要求说明理由和范围。

例如，`src/feature.rs` 这样加载 `src/feature_tests.rs`：

```rust
#[cfg(test)]
#[path = "feature_tests.rs"]
mod tests;
```

测试样例、断言快照与测试辅助代码归测试层，预览样例归显式 mock 适配；测试依赖为开发依赖，构建配置排除测试产物。
tsconfig 的 exclude 本身不是导入防火墙。用合成数据及确定性断言，只回收测试自己拥有的端口、进程和临时目录。

## 验证与交付

实现中运行最小相关测试，最终文件上再完成受影响的集成检查；实际命令与开发指南配套使用。

| 改动 | 验证范围 |
| --- | --- |
| 文档、规则、Skill | Markdown、相对链接、双语事实和规则一致性，校验 Skill 元数据 |
| 边界／工具行为 | 有意义的禁止反例及允许正例、Python 测试、真实仓库边界检查 |
| 共享 UI/client、壳前端 | 相关测试／类型检查、`npm run check`、受影响的 Web／Desktop 前端构建 |
| Core/protocol/runtime | 相关 Cargo 测试、fmt／Clippy；协议变化重新生成 TS 并检查漂移 |
| 原生桌面适配 | 独立原生 Cargo 测试／构建和相应 OS 验证；前端构建不能覆盖原生行为 |
| 真实持久化、宿主、Connector、资源指标 | 明确授权的实际运行及故障场景；模拟与诊断结果不能证明这些能力 |

当前本机 Node 22.16 执行含 TS 导入的 mock 测试时，需要 `NODE_OPTIONS=--experimental-strip-types`，
例如 `NODE_OPTIONS=--experimental-strip-types npm run check`。先检查实际工具版本，不以升级全局工具或改锁文件伪装检查通过。

回读生产者／消费者接口、可选任务流程、过期／并发变化、资源释放和失败反馈。
交付前核对完整 diff 与未跟踪文件，记录命令／结果和未验证边界，说明改动、原因、风险及下一步允许的操作。
浏览器、原生运行、持久化和真实宿主验收分别记录，相关代码变化后重新判断旧证据是否仍适用。

边界脚本使用已锁定的 TypeScript 解析前端语法，该部分需要已安装的 Node/npm 工具链。
它检查声明依赖和支持的字面量本地导入，不是完整构建解析、类型检查、安全沙箱或业务归属的自动证明。
计算得到的导入路径、自定义构建别名及第三方依赖图仍需评审。
当前导入扫描不遍历迁入 JS/JSX 的 JSDoc 类型元数据，该部分的类型归属约束仍由评审核对。
本地通过不代表远端 CI 已运行，也不代表远端分支保护已经设置。

## 交接给另一个 Agent

```text
先读 AGENTS.md、docs/engineering/standards.zh-CN.md 和所属 BOUNDARY.md。
目标／期望用户行为：
所属模块／允许改动范围：
必须保持的约束／失败情况：
预期测试与证据：
已有改动保护：
本次授权的 Git／外部操作（如有）：
```

规则变化持续更新所属现行文档。例外说明理由及范围；不另建相互竞争的带日期规则全集，也不向每个任务、Skill 或宿主配置复制整套规范。
