# 资源与响应验收

[English](resource-acceptance.md) | [简体中文](resource-acceptance.zh-CN.md)

状态：**尚未测量的设计预算**，2026-10-29 延续既有门槛。
选择 Rust/Tauri 不代表通过。首轮参考 Mac mini M4／24 GiB，记录实际 OS、架构、电源、
构建与组件版本；其他平台建立各自参考机和结果，调整预算必须评审。

## 计量约定

使用发行构建，不开开发服务器、DevTools 或热更新。
固定带哈希的负载：一万任务、十万阶段／同步事件、两万产物索引、1 GiB 分段历史日志；
同时固定正文大小、分页、租约、轮询和可视范围，启动不全量读取历史。

CPU 为进程组 CPU 时间／经过时间，一个逻辑核为 100%，每秒采样。
静态场景预热 60 秒后采样至少 5 分钟；footprint 每 10 秒采样，至少 30 个样本。
记录采样开销和采样峰值，不冒充连续观测峰值。

macOS 使用去重的进程组 footprint，不相加 RSS。
归属 Core、适配、宿主 UI、Desktop 及其 WebView/XPC/GPU/网络进程，
在相同负载下做启用／禁用或打开／关闭配对。
即使某门槛只隔离 Reed 控制层，仍报告真实 CLI/Agent 和全组总资源。
归属不清不能记作零占用。

## 预算

| --- | --- | --- |
| RSC01 | Core-only 空闲，无 Agent/CLI，台架租约保活 | Core footprint P95 ≤150 MiB，平均 CPU ≤0.5%，1 秒 CPU P95 ≤2%，无 Desktop/WebView |
| RSC02 | 单端插件启用、面板关闭 | 适配／宿主增量 ≤40 MiB，平均 CPU 增量 ≤0.2 个百分点；Core 满足 RSC01 |
| RSC03 | 四端启用、面板关闭 | 配对的整组 footprint 增量 ≤120 MiB，Core+适配平均 CPU ≤1%，一个写入者 |
| RSC04 | Core 已运行，Desktop 静态页 | Desktop 及关联 WebView 增量 ≤200 MiB，平均 CPU 增量 ≤0.5 个百分点 |
| RSC05 | 宿主保持连接时退出 Desktop | 5 秒内释放桌面进程／订阅，稳定 60 秒再采样 5 分钟，Core+适配 P95 ≤打开桌面前基线+20 MiB；执行继续 |
| RSC06 | 模拟同步：1,000 外部项，每变更 1 KiB，合计 20 次/秒，10 分钟 | Core P95 ≤250 MiB，平均 CPU ≤20%，提交到各活动视图更新 P95 ≤250 ms；真实网络／CLI 另列 |
| RSC07 | 后续 1/4 路隔离执行流，合计 20 事件/秒 | Core+实际 Bridge/控制运行时合计 P95 ≤250 MiB，投影 P95 ≤250 ms；真实 Agent／工具及总量另列 |
| RSC08 | 1 GiB 历史、每事件 1 KiB，合计 20/秒，长挂载日志 | Core 单页额外内存 ≤32 MiB，各计量集合及整组末 30 分钟增长 ≤15 MiB；停载 5 分钟后 ≤同最终数据／视图基线+30 MiB |
| RSC09 | 显式后台同步，单来源无变更，每 60 秒轮询，30 分钟 | Core P95 ≤150 MiB，平均 CPU ≤0.5%；CLI 峰值／总量／次数另报；客户端不增加轮询次数 |
| RSC10 | 单／四端静态任务 UI，再独立开关循环 | UI P95 增量 ≤200/600 MiB，平均 CPU 增量 ≤0.5/2 个百分点；最终关闭四端组 ≤面板关闭基线+40 MiB |

RSC03 是四端整体配对，不相加四份单端差值。
RSC10 的 UI 增量以插件已启用、面板关闭为基线，适配仍受 RSC02/03 约束。
托盘单列。RSC06/07 模拟流不证明真实来源吞吐或四个真实 Agent 并行。

## 长日志与视图回收

RSC08 分别验证四端 UI 组合与 Tauri 组合：

- A1：同一日志容器连续尾随 60 分钟，不翻页、不切任务、不关闭、不重挂载。
- A2：同任务／容器尾随，同时每 5 秒读取下一固定 256 KiB 历史页，持续 60 分钟；
  单页硬上限 1 MiB，不关闭或重挂载。
- B：独立做 20 轮打开 30 秒／关闭 30 秒，每轮切两个固定任务。
  最终关闭后稳定 60 秒再采样 5 分钟，P95 ≤同负载关闭视图基线+30 MiB。

A1/A2 的增长分别取各集合第 55–60 分钟 P95 减第 25–30 分钟 P95。
停载后保持同一静态日志视图，用最终等量数据和相同可视范围预热的对照实例作基线。
B 不能抵扣 A1/A2 泄漏，周期重建容器不能代替连续挂载。
Core／适配／UI／Desktop／全组分别计量。
Core P95 仍 ≤250 MiB，适配保持 40/120 MiB，宿主 UI 200/600 MiB，Desktop 200 MiB。
CPU 同时按 RSC06 控制负载预算复核，固定但巨大的缓存不能只因增长小而通过。

RSC10 先持续静态打开、预热 60 秒并采样 5 分钟，再独立对各端做 20 轮开关；
最终关闭后稳定 60 秒再采样 5 分钟，不把关闭期平均进打开时的 CPU。
记录订阅和任务缓存释放，不只数窗口。

## 启动与就绪

至少 30 次启动，报告 P50/P95/max。
正常负载无未决工作时，新 Core 进程到认证、恢复、schema 检查及合法任务读写均可用：
P95 ≤2 秒，仅端口监听不算 ready。
Desktop 到列表／详情可操作：Core 已可用时 P95 ≤2 秒，包含冷 Core 启动时 ≤3 秒，
启动画面不代表可交互。

故障恢复启动单列：10 秒内显示诊断，安全恢复前保持禁写，超预算也不能跳过。
新进程／文件缓存暖启动与机器重启／缓存冷启动分开。
Core 单页查询 P95 ≤100 ms，界面更新用端到端 trace，不能只量服务端发送。
默认仅在全部客户端租约结束，且无自有工作、后台同步或其他驻留原因时，
等待 60 秒后于 5 秒内空闲退出。
显式停止和维护状态必须阻止自动立即重启。

本轮没有 RSC 实测或基准台架，也没有承载这些业务/容量负载的目标二进制和宿主验收；既有诊断二进制不等于资源目标产品。
在对应阶段建立台架，原始样本与公开摘要分别管理。

## 与功能验收及语言选择的关系

本次整合不改变 RSC01–RSC10 的数值。RF06/22 复用此处资源场景，
前者检查回收，后者检查补读/控制响应等正确性，不另设第二套预算。
必须记录单条上限、总队列字节和在途请求/生产任务，不能用稳定队列长度掩盖无限等待任务。
RSC01/03 测量可显式用台架租约保活，台架另计；不让正式插件的普通心跳阻止生产空闲退出。

先测当前 Rust 发布构建，未达标调查具体热点，不直接归咎语言或自动放宽预算。
如重新评估 Rust/TS，采用相同业务功能、存储/持久化等级、CLI/IPC、负载与故障语义、
OS/arch 和发行构建；TS 包含其运行条件，Rust 包含实际系统库/辅助进程。
比较冷启动、footprint/CPU、日志与重建有界性、安装升级及维护成本，
不拿 Rust 诊断空壳与完整 TS 产品比较，也不为对照维护双生产 Core。
未测的真实 CLI/Agent/宿主成本明确缺证，模拟通过不替代实际全组验收。

阶段适用性见[实施计划](implementation-plan.zh-CN.md)：M3 底座探针只能提供预验；
RSC01 的业务容量/合法读写从 M4 验证，四端/Tauri 的完整 RSC08/10 在 M8 收口。
不增加或放宽数值预算，也不把尚未实现的测试夹具记为已通过。

## 冻结基线后的相对回归复核

补齐既有总方案的回归口径：同版本负载/配置/平台冻结基线后，footprint 增量超过
max(基线的 10%, 20 MiB)、P95 延迟增量超过 max(基线的 15%, 100 ms)，
或空闲 CPU 增加超过 0.2 个百分点时触发复核；绝对 RSC 预算仍必须满足。
保留异常/失败样本，不挑最好一次，也不将 fixture 改动混入同基线比较。
这是已有预算的追溯补齐，不是本轮性能成绩或放宽门槛。

## 可选云复制的后续计量

默认关闭复制的本地 M1–M8 保留全部 RSC 数值，不引入云连接/账号或额外常驻服务。
未来 C1/C2 先固定设备数量、变更/附件大小、离线积压、冲突、传输及 checkpoint 负载，
再定义云启用后的本机 CPU/内存/网络/回落和服务端成本/延迟预算。
这些未测项目不能沿用 Core-only、模拟云效或单机 UI 的成绩。
同步关闭不丢未上传数据/未决影响，后台复制必须有显式驻留原因；执行边界见[复制专题](../architecture/replication.md)。
