## 依赖排序后的八项 MVP 增量

这是原 P0–P7 的单一路线；旧编号仅保留追溯，不另建 CP/RFP 排期。
“细化”沿用原设计和对象，不重建同义服务。

| 增量 / 原阶段 | 实施内容 | 前置与退出证据 | 不做的代价 |
| --- | --- | --- | --- |
| M1 边界与契约细化 / P1 | 保留三 Rust crate/独立 Tauri workspace；应用端口/wire DTO、生成/校验/兼容；稳定对象/数据集/设备作用域及可复制分类预留，产品规格权威 | 基础骨架；RF21 依赖反例、生成漂移、固定版本组合；诊断生成不计业务完成 | 按旧 TS 目录建设，各壳复制规则 |

| M3 独立生命周期细化 / P2/P7 | 用户级发现/启动、profile 单写、准入/排空、活动/租约、显式停止、SQLite/迁移底座及凭据；数据与设备认证分离，隔离探针验证七步升级 | M1/M2 对应平台；RF01–05/09/25 的底座子场景；持久化探针/重启/迁移成立，不宣告业务 ready 或容量 RSC 通过 | 多后台、自动复活、升级抢写或只能靠 Desktop 恢复 |

| M5 共享交互/一致数据 / P1/P6 | 审阅迁移原型样式/资产到 UI/Web；列表/个人看板/右抽屉、任务/分支视角；快照水位/补读、有界 client/日志；系统主题/中英设置 | M1/M4；RF06/11/13/21/22；已有 UI 做有界/资源预验，四端/Tauri 的 RSC08/10 待 M8；保持视觉和上下文 | 丢更新、无限缓冲或 UI 绕开 Core |
| M6 原生执行/工作区/文档细化 / P4/P5 | DSH 后 ZCode；准备/提交/接纳/终态/验收分开；可信会话、准确 worktree/cwd、版本文档、多仓关系和归属清理 | M2 对应宿主、M3–M5；RF08–13/23 的 DSH/ZCode 子场景；真实 ID/结果、旧目录拒绝；外派不替代原生会话 | 关联即授权、准备即执行、抢占或误删用户工作 |
| M7 云效双向同步细化 / P3 | 官方 CLI、多连接来源、配置/发现草稿、主体/映射、规范对象 outbox、B/R/D、unknown/风险恢复 | M2 逐操作能力、M4/M5；RF14–20；授权测试账号真实写/回读另留证；RSC06/09 | 重复副作用、跨连接绕过阻塞，当前值相等冒充请求确认 |

M2 可用明确标为诊断/模拟的最小探针验证入口，不把探针当真实业务闭环。
某端必需能力未证实，阻塞该端及“四端完整支持”，不阻止无关本地内部切片；
不能自行下调产品目标。M7 可在本地契约成立后与独立宿主适配工作并行，
M6/M7 在 M8 组合验证。验收随各增量执行，不等最后才补恢复与安全检查。

## 已有机制与范围

- Operation、事件表、outbox、占用和关系是已有设计；快照屏障与原目标回复是契约细化，
  不建设消息总线、通用调度/审批平台或每表仓储。
- 安装仍为 Core-only + 各端插件两步，Tauri 可选；共享 UI/client 在 Reed 单一维护，
  ai-code 消费固定制品并拥有薄适配/市场。独立构建见[开发指南](development.zh-CN.md)。
- 原型/资产迁移与契约替换分开；保留确认的视觉。localStorage 无明确导入路径不宣称迁成
  SQLite。领域/操作文档已迁移，不重复安排此工作。
- P8 保留后续反向集成：通过有版本公开 Bridge/SDK/CLI/ACP 实现 AgentExecutor，
  先单引擎再有界多引擎；自有审批/停止/恢复及 RSC07 分别验证，不提前加入 MVP。
- 先按当前 Rust 发布构建测 RSC；仅在重开语言决策时做同功能/负载/平台的随包 TS 对照，
  同时报维护成本，不维护双生产 Core，不凭 Rust 判性能通过。

## 必须保留的产品验收

1. 本地任务不依赖云效；四阶段可人工或 Agent 执行，LLM 只提议。
   任务/执行/验收/交付/同步分开；模板/范围变化使相关证据待复核，不改历史。
2. 个人看板待办/进行中/评审中/完成可拖拽；评审/完成检查当前产出与验收，
   不满足留原列并说明；右侧抽屉保留筛选/滚动，双视角查看没有 Git 副作用。
3. 文档/会话/仓库/分支/worktree 可追溯到任务阶段；关联不授予控制。
   缺失/变化材料、失联、旧 cwd 可见；清理不删除非本操作资源。
4. 外部数据标明 Connector/来源；配置、检测、组织/项目选择、状态映射在界面可操作。
   模拟发现不是真扫描，Token 枚举组织等只在已验证能力内开放。
5. 本地保存与外部确认分开；无 CAS 不宣称严格防覆盖，unknown 不盲重试，
   换连接不清历史；范围/完成依据变化重新检查未发意图。
6. 未安装/未打开/退出/卸载 Desktop 不破坏插件已声明功能和共享数据。
   四端 L0–L3 必需项分别通过；外部页面或独立 Agent 会话不替代宿主内操作。

## 阶段退出的适用性与依赖闭合

RF 引用是场景组归属，不要求前置阶段运行依赖后续功能的全部子场景。
M1–M8 的前置依赖按表执行，补充以下退出界线；未来 C1–C3 不成为前置：

| 阶段 | 当期必须完成 | 留给后继的证据 |
| --- | --- | --- |
| M1/M2 | 静态契约/兼容样例、最小宿主和 CLI 探针、冻结负载与开放条件 | 正式认证/持久化、真实任务和来源业务闭环不能用 mock 通过 |
| M3 | 同一 runtime 内的 SQLite/事务/迁移底座、隔离探针读写、锁/凭据/停止和恢复；不新建另一探针服务 | 底座探针用隔离夹具调用真实适配，不向正式 API 开通用 SQL/探针写口；M4 加业务表/ready，M6/M7 加真实效果，M8 复验升级组合 |
| M4 | 人工完整流程、最小版本产物/稳定关系/只读仓库观察、事务回执与恢复；建立真实领域测试 | M5 用这些关系构建双视角；M6 再加可信控制绑定、自动 worktree/多仓交接，不反向阻塞人工流程 |
| M5–M7 | 各自已实现 UI/宿主/连接器的功能与故障子场景，资源预验单列 | M8 补齐四端和 Tauri 的全部适用组合；P8 自有引擎交互仍不提前要求 |
| M8 | 必需产品能力全部成立、版本/平台矩阵和 RF/RSC 证据完整；拒绝路径可复验 | 仍缺必需原生页面/绑定/执行或双向写入能力时保留产品阻塞，不以“适用项”删去目标 |

RSC01 的固定业务容量和“合法任务读写 ready”从 M4 起执行；M3 的探针耗时/占用不能
填成该成绩。RSC08/10 的四端/Tauri组合在 M8 收口，已实现端可提前留证但不能代表全组。
M2 探针即使成功，仍需后续在同版本真实业务路径复验。

M1 固定有版本的 HostAdapter 控制契约，M2 验证 Core 到插件受信端的命令/反馈通路，
M6/M8 实现各端；不是到 M8 才解决启动/跨仓输入契约。
M4 的关系仅引用/导航，原生控制和创建隔离工作区不会提前获得授权。

## 云同步预留：本地增量与后续独立阶段

已确认“个人多设备优先、团队后续”，正式范围见[复制专题](../architecture/replication.md)
与 [ADR-0002](../decisions/0002-optional-cloud-replication.zh-CN.md)。
现有八项 MVP 不增加云服务交付，不以账号/网络/部署作为本地验收前置；
预留只落在已有模块/用例边界，不创建空服务、网络 worker 或通用同步引擎。

| 本地增量 | 本轮纳入的设计预留 | 未来实现时才承担 |
| --- | --- | --- |
| M1 | 稳定跨设备对象/数据集/设备身份；local revision/共享版本、请求/复制身份分开；白名单与协议命名空间 | 云协议 DTO/账号/空间实现，新的生成样例与兼容矩阵 |
| M3 | 数据、设备认证/副本和安全存储分开；恢复/备份不复制控制能力 | 云配对、服务注册、复制 checkpoint/恢复测试 |
| M4 | 业务事务有版本/来源及可接变更采集的边界，关系/证据区分内容与设备定位 | 开启复制后的白名单变更日志/上传队列；开启前历史用一致快照引导，不无限保留全量云日志 |
| M8 | 本地构建/安装不带云服务依赖，无账号默认不联网；当前 RF21/26/RSC 口径保持 | 云端制品、部署和云启用负载不计作本地已通过 |

以下为后续可选云路线，不是第九个本地增量，也不依赖先完成 P8 反向 Agent 集成。
C1/C2/C3 可以按产品目标单独授权排期；源码/模拟/真实多设备与外部效果证据分别保存。

| 阶段 | 前置与交付 | 退出条件 |
| --- | --- | --- |
| C1 个人数据复制 | M1/M3/M4 的真实本地契约/存储、M5 中所选任务/冲突 UI 可用；建立 services/reed-server 独立 workspace/锁/存储/部署；账号/个人空间/设备、元数据与选定附件、初始快照、增量/去重/冲突/撤销/恢复 | RF27–29/31–33，RF30 的归属/禁止抢主子场景；两台真实设备离线编辑/重连、白名单无秘密、未下载/缺失区别；本地既有执行继续，但任何新共享原生派发/来源写入均禁用（手动/规则同等），核查/停止和非共享任务除外 |
| C2 共享动作的受控启用 | C1、M6/M7 中对应动作已真实验收；共享基线接纳与派发占用/稳定意图/所属设备形成明确先后契约；云效单设备及原生任务归属、显式交接/核查 | RF29/30/31/33 的真实效果子场景；旧设备不可达/unknown 不抢主，复制不重放效果，无确认/有冲突时新共享副作用保持待处理；云效无 CAS 界限照实保留 |
| C3 团队空间 | C1/C2 中所选开放能力；在 SyncSpace 上加成员/角色/可见范围、审计与撤权；个人数据显式选择共享 | RF34 及跨空间拒绝/离线旧权限/成员撤销；编辑共享记录不等于获得执行设备控制；不宣称即时擦除离线缓存 |

C1 复制确认不等于云效回写、Agent 执行或另一设备已拉取；
C2 只有实际验收的动作可启用，C1 手动按钮也不能绕过门槛；不能因数据已复制就把全部宿主/来源动作宣称可跨设备执行。
独立 AgentExecutor 的远程运行/SDK/多引擎仍按 P8 自己验证，C2 不替代该证据。
云端账号、附件/备份保护、部署/恢复兼容与启用后的资源/网络负载在各云阶段先固定再验，
本轮不提供未经测量的资源承诺。RF27–34 仅为未来场景，不并入当前 M8 的 RF01–26。
