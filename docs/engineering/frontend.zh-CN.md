# 前端开发

[English](frontend.md) | [简体中文](frontend.zh-CN.md)

产品 UI 现在只有一份实现，位于 `packages/ui/src/workbench`；Web 和 Tauri 均通过
各自正常的 `src/main.tsx` 装配。不再保留独立 `demo-ui` 工程或桌面页面副本。
后续 UI、交互和操作流讨论在这里推进，ai-code 中旧原型仅用于历史追溯。

## 目录与边界

| 路径 | 职责 |
| --- | --- |
| `packages/ui/src/workbench/App.jsx` | 导航与临时呈现状态 |
| `packages/ui/src/workbench/pages/` | 任务列表、任务详情及会话／分支视图 |
| `packages/ui/src/workbench/` | 共享组件、国际化、样式和类型化装配 |
| `packages/ui/src/mock/` | 样例、模拟规则、连接器场景与存储适配 |
| `packages/ui/public/assets/` | 两端共享的已确认品牌与来源图标 |
| `apps/web/src/main.tsx`、`apps/desktop/src/main.tsx` | 明确将 WorkbenchRoot 与 mock runtime 装配 |
| `apps/*/src/diagnostics.tsx` | 保留 FoundationApp 健康诊断装配 |

`@reed/ui` 导出 WorkbenchRoot、FoundationApp 与内部前端端口类型。
`@reed/ui/mock` 是独立显式入口，不从主 UI barrel 导出。
页面通过注入的 runtime 读取状态和发起操作，不静态导入模拟规则。
Rust Core、协议和生成客户端契约未变。

> 2026-10-30 目标业务已统一为任务类型、五状态及可选流程，见[业务模型](../product/domain-model.md)与[交互基线](../product/interaction.md)。
> 共享前端已按该设计实现本地模拟交互；四个研发步骤仅在显式采用流程时出现。Core 业务和真实宿主／来源未接入。

## 当前模拟模式

正式前端源码暂由模拟适配器提供数据，供继续确认产品操作流；没有接真实 Agent、Git、CLI、
凭据或来源写入。相关流程和「关于 Reed」仍明确标注模拟。
保留 `reed-demo-v2` 键及 `reed-locale`／`reed-theme`；新保存使用 version 5，仅回读 version 5 草稿，
更早信封按演示阶段约定回退到新版建模样例。
旧阶段完成不补造任务级验收：保留资料和原状态历史，并将缺少任务完成依据的旧完成／归档项标为处理中待核查。
草稿损坏或读取失败回退到原有样例；写入失败保留内存状态并显示保存失败。
浏览器和 Tauri 的模拟存储仍相互独立。

2026-11-01：任务详情与创建流程已移除「可选流程模板／内部步骤」，任务流改由任务关联表达；
任务描述、目标、产物正文与评论使用 Markdown，并支持图片粘贴／上传／链接；mock 图片以
有大小限制的 data URL 保存，文档保持只读。旧流程数据仅保留历史展示，不再参与完成判定。

2026-11-04：mock 模型加入显式的项目工作区层。项目聚合多个本地目录；git 目录即工程
（以目录名命名）并持有分支。Agent 工作区记录各 Agent 侧的项目，通过共享目录收敛到
Reed 项目：候选可显式关联或忽略，目录单项目归属，候选提升为新项目时未提供自有名称则
借用 Agent 侧名称。会话挂接 Agent 工作区；任务保留 `projectId` 及展示镜像
（`project`、`repo`、会话 `host`），镜像是呈现便利而非第二事实源。绑定宿主会话时确保
该 Agent 存在已关联工作区。项目视图与导航整合在下一步实现。

同日后续收敛让身份始终优先：本地任务以新项目名归属时即创建该唯一名项目，编辑归属时
`projectId` 随显示名一起迁移。仓库镜像在创建/编辑时即在任务所属项目范围内解析目录身份；
加载回填不做跨项目或歧义的按名猜测，旧的跨项目目录身份在加载时丢弃。只有已注册宿主
可以接入会话（未注册宿主不再出现在选项中且被拒绝）；资源抽屉「查看任务」先关闭自身
再导航；目录关联失败时保留输入与可见错误。

本地 v5 旧草稿若只保存了非空项目名，加载时按名称补齐缺失项目并回填任务身份，
保留任务正文、讨论和历史；未归组任务及未关联的外部来源项目不会被自动建项。
项目变更按实际目录身份应用已有资源的换仓保护，即使两边仓库同名也不能隐式替换
会话或工作区所用仓库。关系图打开任务节点时先关闭关系图，再显示任务抽屉。

同日晚些时候项目视图落地：维护目录（git 工程及其分支）、按 Agent 工作区列出会话
（会话行带分支与任务标注）、提供候选工作区的关联／提升／忽略操作，并内嵌项目任务
列表。顶层「会话／分支」导航入口随 `ResourcePage` 一并移除；会话与分支详情改由共享
的资源抽屉承载，可从项目视图、任务抽屉的关联弹窗与任务详情资源行打开。
目录维护改由侧栏编辑入口的「项目目录」弹窗承担：用户输入绝对路径（或经目录选择器，
浏览器端只能取到目录名），git／普通类型由系统自动判定而非用户选择——判定在 mock 中
为模拟规则，真实判定归 Core 的文件系统适配器。侧栏项目可展开二级菜单，按 Agent 分组
列出会话，点击直接打开资源抽屉。

Tauri Demo 构建变体保留 `dev.reed.desktop.demo` 与原本地 origin，重新构建不会重置已有演示数据；
它与普通 Desktop 构建已使用同一套前端，不代表正式 Core 共享存储或同步已实现。

`workbench/ports.ts` 的同步快照／操作接口只是内部迁移接口，不是稳定业务模型、生成的通信契约，
也不保证未来异步 Core 适配可以原样替换。先确认用户操作，再校准业务模型与 Core 契约。


Web 与 Desktop 前端产物均保留 `/diagnostics.html`，Web 开发代理和原生健康诊断桥维持原行为。
默认工作台不启动或调用 Core。

UI 包通过 Vite library 生成独立 index／mock ESM，再由 TypeScript 生成声明；旧 JSX 导入会被
正确打包，不发布指向不存在 `.jsx` 文件的产物。Node 独立制品检查验证两种入口可在无浏览器全局
变量时导入；应用构建使用同一源代码。

## 双语与代码标准

新增装配、Context、偏好与存储端口使用严格 TypeScript。迁入的 JS／JSX 为保持行为暂时保留，
并格式化、拆分成可维护的页面模块；明确使用 `allowJs: true`／`checkJs: false`，声明生成不代表
旧组件已经完全类型安全。新模块应使用 TS／TSX，随着交互模型收敛逐步补齐视图类型。

固定文案集中在 `workbench/locales`；任务标题、正文、ID 和来源名保持数据原样。
数量使用完整的单复数文案分组。列表保留完整状态、随宽度逐步收起次要列，手机宽度将状态放到标题下；
不调整字号、配色或已确认素材。

`npm run format:frontend`／`npm run check:frontend-format` 管理迁入源码格式。
测试覆盖原模拟规则、适配存储失败、SSR 装配、语言与依赖边界；浏览器／原生走查独立记录，
不替代真实 Core、宿主和来源验收。

桌面导出通过 `WorkbenchFileExport` 注入，原生 SDK 只在 `apps/desktop` 中使用。
共享页面没有原生 SDK 依赖；导出端口属于壳的 UI 能力，不是 Core 业务契约。
网页使用原下载行为，原生保存命令不接受目标目录参数。

文档下载在共享 UI 中将显示标题转换为安全的 Markdown 文件名；不修改保存的标题或版本。
临时表单／会话答复草稿属于前端状态；浏览器存储禁用或缓存不可用时仍可操作，不作为业务存储。

演示恢复仅在 mock 适配器内校验当前可渲染结构，残缺快照回退样例；这不是正式 Core 数据校验。

## 本地任务的创建与开始处理

最小任务的标题、类型和生命周期始终有值；类型默认未分类，创建默认为待办。
任务内容、验收条件及关系选填。详情默认阅读，通过“编辑任务”修改基本信息；
任务类型明确标注，空的验收条件和关系仍保留紧凑查看区。

点击状态即可切换；仅标题的任务可由待办直接切到处理中或已完成，不再设置独立的开始、
提交评审或处理结果表单。“评审中”保留为可选的等待核对状态。有验收条件时，切换为已完成须在当前页面逐项核对。
已采用流程承诺、必要关系、执行占用及显式通过要求仍有效。已完成可通过状态重开；
仅已完成可归档，已归档恢复到已完成。看板移动复用相同检查，不自动启动 Agent。

任务下方提供可选的评论列表和输入框，完成及归档后仍可评论。评论独立保存作者、时间和纯文本，
不创建产物或执行依据，不改变任务完成快照。已有文档仍作为关联文档保留，历史完成依据可从更多菜单查看。
“最近活动”显示最近四条事件，“查看全部活动”打开完整记录。
这些仍为浏览器存储的本地模拟交互，不是 Core 任务或正式持久化。

新建表单只有标题必填；项目可未归组，仓库和参考资料收纳在「关联上下文」中，允许后补。
说明是独立背景草稿，不自动生成阶段产物或验收。新任务创建后保留在待办，
切换状态为「处理中」后，可人工处理或单独准备 Agent 执行。
看板内创建继续使用右侧详情，保留原看板筛选与上下文；选定项目筛选时预填该项目。

详情「完善任务信息」可补充项目、仓库、说明和参考资料。新建表单保留未提交草稿，
编辑取消后重新打开以最新已保存内容为准，避免旧草稿回退新标题。
资料仅保存模拟文件路径／HTTP(S) 链接的名称与位置，不读取文件或扫描仓库。
首次补仓库允许保留无具体仓库的已结束需求／设计会话；已有仓库、活动／未知执行或
代码工作区仍受换绑保护。开发工作区准备要求已关联仓库。

这些动作属于 mock 适配中的演示规则，不是 Rust Core 业务、真实文件接入或正式契约。
新增回归覆盖仅标题创建、五类任务同一生命周期、创建不执行、上下文与仓库保护、旧缓存及中英文渲染。
通用详情支持可选流程、范围与验收条件、关联文档、直接状态切换、任务评论与只读完成历史；旧评审/产物命令仅保留兼容，
内部步骤确认与任务完成分开，失败执行有显式重试入口，编辑产物保留真实结果并要求明确必要工作覆盖。
浏览器交互与真实宿主验收独立报告，不从这些测试推导通过。

本轮前端模拟范围与实际检查见[统一任务前端验证记录](task-flow-ui-verification.md)。

## Markdown 图片编辑

图片处理完成前禁止提交所属表单；关闭编辑器后忽略晚到结果。
所有程序插入先核对字段最终长度，超过限制时保留原文并提示。
文件名和带括号的 URL 通过同一行内 Markdown 读取规则往返呈现。

两种 Desktop 变体的 `img-src` 均允许 HTTP(S) 图片，与 Web 编辑器一致；
渲染外链图片时会发起普通图片请求。脚本和接口连接来源保持原有限制。
[Tauri CSP 机制](https://v2.tauri.app/security/csp/)将该策略应用于打包页面，
前端构建本身不构成原生运行验证。上传图片仍作为有大小限制的 data URL 存入本地 mock 草稿。

DOM 交互测试使用固定版本 jsdom 26.1.0，仅作为开发依赖，覆盖处理中提交、取消及插入长度限制，
不替代浏览器或原生图片解码与网络验证。

## 任务详情呈现

任务内容直接承接标题与属性，其后保留独立、选填的目标与验收条件、评论和活动。
既有元数据、完成记录、编辑权限和操作回调均保留。任务关系、任务上下文和关联资源集中在一个辅助区：
宽屏完整页使用侧栏，抽屉或窄窗口放在阅读区下方。同一文档只展示一次，仍保留全部版本、执行结果、
适用范围及原有核对复用入口。空字段保留查看位置并收紧间距。
这次布局调整只改变呈现，不修改模拟业务规则或存储格式。

2026-11-03：辅助区不再绘制为视觉上独立的区域。抽屉与窄窗口中的灰底盒子被移除，
宽屏侧栏取消底色差异；任务关系、任务信息、关联资源改用与阅读模块相同的分节原语
（统一的节标题、分隔线与间距）。模块边界保持在模块一级，而不是把页面切成两种样式的区域。
任务时间戳与本地保存状态也移出阅读列，作为支撑区之后的页面级页脚渲染：
单列形态不再夹在两组模块中间，宽屏在两栏下方以一条状态页脚收尾。
本地保存失败额外在阅读内容上方钉一条常驻报警（sticky，`role="alert"`），
下一次保存成功后自动消失；保存成功保持安静，仅由页脚陈述。
