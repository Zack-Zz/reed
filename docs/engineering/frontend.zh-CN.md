# 前端开发

[English](frontend.md) | [简体中文](frontend.zh-CN.md)

产品 UI 现在只有一份实现，位于 `packages/ui/src/workbench`；Web 和 Tauri 均通过
各自正常的 `src/main.tsx` 装配。不再保留独立 `demo-ui` 工程或桌面页面副本。
后续 UI、交互和操作流讨论在这里推进，ai-code 中旧原型仅用于历史追溯。

## 目录与边界

| 路径 | 职责 |
| --- | --- |
| `packages/ui/src/workbench/App.jsx` | 导航与临时呈现状态 |
| `packages/ui/src/workbench/pages/` | 任务列表、任务详情及会话／分支视图 |
| `packages/ui/src/workbench/` | 共享组件、国际化、样式和类型化装配 |
| `packages/ui/src/mock/` | 样例、模拟规则、连接器场景与存储适配 |
| `packages/ui/public/assets/` | 两端共享的已确认品牌与来源图标 |
| `apps/web/src/main.tsx`、`apps/desktop/src/main.tsx` | 明确将 WorkbenchRoot 与 mock runtime 装配 |
| `apps/*/src/diagnostics.tsx` | 保留 FoundationApp 健康诊断装配 |

`@reed/ui` 导出 WorkbenchRoot、FoundationApp 与内部前端端口类型。
`@reed/ui/mock` 是独立显式入口，不从主 UI barrel 导出。
页面通过注入的 runtime 读取状态和发起操作，不静态导入模拟规则。
Rust Core、协议和生成客户端契约未变。

> 2026-10-30 目标业务已统一为任务类型、五状态及可选流程，见[业务模型](../product/domain-model.md)与[交互基线](../product/interaction.md)。
> 共享前端已按该设计实现本地模拟交互；四个研发步骤仅在显式采用流程时出现。Core 业务和真实宿主／来源未接入。

## 当前模拟模式

正式前端源码暂由模拟适配器提供数据，供继续确认产品操作流；没有接真实 Agent、Git、CLI、
凭据或来源写入。相关流程和「关于 Reed」仍明确标注模拟。
保留 `reed-demo-v2` 键及 `reed-locale`／`reed-theme`；新保存使用 version 3，兼容读取旧 version 2。
旧阶段完成不补造任务级验收：保留资料和原状态历史，并将缺少任务完成依据的旧完成／归档项标为处理中待核查。
草稿损坏或读取失败回退到原有样例；写入失败保留内存状态并显示保存失败。
浏览器和 Tauri 的模拟存储仍相互独立。

Tauri Demo 构建变体保留 `dev.reed.desktop.demo` 与原本地 origin，重新构建不会重置已有演示数据；
它与普通 Desktop 构建已使用同一套前端，不代表正式 Core 共享存储或同步已实现。

`workbench/ports.ts` 的同步快照／操作接口只是内部迁移接口，不是稳定业务模型、生成的通信契约，
也不保证未来异步 Core 适配可以原样替换。先确认用户操作，再校准业务模型与 Core 契约。

## 构建与验证

```sh
npm ci
npm run build:ui
npm run dev:web                 # http://127.0.0.1:1420/
npm run dev:desktop:demo        # 同一正式 UI，保留演示应用身份
npm run build:web
npm run build:desktop:demo:ui
npm test -w @reed/ui
npm run check
```

Web 与 Desktop 前端产物均保留 `/diagnostics.html`，Web 开发代理和原生健康诊断桥维持原行为。
默认工作台不启动或调用 Core。

UI 包通过 Vite library 生成独立 index／mock ESM，再由 TypeScript 生成声明；旧 JSX 导入会被
正确打包，不发布指向不存在 `.jsx` 文件的产物。Node 独立制品检查验证两种入口可在无浏览器全局
变量时导入；应用构建使用同一源代码。

## 双语与代码标准

新增装配、Context、偏好与存储端口使用严格 TypeScript。迁入的 JS／JSX 为保持行为暂时保留，
并格式化、拆分成可维护的页面模块；明确使用 `allowJs: true`／`checkJs: false`，声明生成不代表
旧组件已经完全类型安全。新模块应使用 TS／TSX，随着交互模型收敛逐步补齐视图类型。

固定文案集中在 `workbench/locales`；任务标题、正文、ID 和来源名保持数据原样。
数量使用完整的单复数文案分组。列表保留完整状态、随宽度逐步收起次要列，手机宽度将状态放到标题下；
不调整字号、配色或已确认素材。

`npm run format:frontend`／`npm run check:frontend-format` 管理迁入源码格式。
测试覆盖原模拟规则、适配存储失败、SSR 装配、语言与依赖边界；浏览器／原生走查独立记录，
不替代真实 Core、宿主和来源验收。

桌面导出通过 `WorkbenchFileExport` 注入，原生 SDK 只在 `apps/desktop` 中使用。
共享页面没有原生 SDK 依赖；导出端口属于壳的 UI 能力，不是 Core 业务契约。
网页使用原下载行为，原生保存命令不接受目标目录参数。

文档下载在共享 UI 中将显示标题转换为安全的 Markdown 文件名；不修改保存的标题或版本。
临时表单／会话答复草稿属于前端状态；浏览器存储禁用或缓存不可用时仍可操作，不作为业务存储。

演示恢复仅在 mock 适配器内校验当前可渲染结构，残缺快照回退样例；这不是正式 Core 数据校验。

## 本地任务的创建与开始处理

新建表单只有标题必填；项目可未归组，仓库和参考资料收纳在「关联上下文」中，允许后补。
说明是独立背景草稿，不自动生成阶段产物或验收。新任务创建后保留在待办，
点击「开始处理」进入处理中，随后可人工处理或单独准备 Agent 执行。
看板内创建继续使用右侧详情，保留原看板筛选与上下文；选定项目筛选时预填该项目。

详情「完善任务信息」可补充项目、仓库、说明和参考资料。新建表单保留未提交草稿，
编辑取消后重新打开以最新已保存内容为准，避免旧草稿回退新标题。
资料仅保存模拟文件路径／HTTP(S) 链接的名称与位置，不读取文件或扫描仓库。
首次补仓库允许保留无具体仓库的已结束需求／设计会话；已有仓库、活动／未知执行或
代码工作区仍受换绑保护。开发工作区准备要求已关联仓库。

这些动作属于 mock 适配中的演示规则，不是 Rust Core 业务、真实文件接入或正式契约。
新增回归覆盖仅标题创建、五类任务同一生命周期、创建不执行、上下文与仓库保护、旧缓存及中英文渲染。
通用详情支持可选流程、范围与验收条件、版本化产物、任务级提交／撤回／通过、归档恢复、理由重开与只读评审历史；
内部步骤确认与任务完成分开，失败执行有显式重试入口，编辑产物保留真实结果并要求明确必要工作覆盖。
浏览器交互与真实宿主验收独立报告，不从这些测试推导通过。

本轮前端模拟范围与实际检查见[统一任务前端验证记录](task-flow-ui-verification.md)。

## 任务关系预览

共享工作台已加入任务关系页、向右拆分树、关联表单及通用详情抽屉。页面布局与临时视图类型在 `workbench`，
关系与必要成果规则在 `mock`；旧 version 3 草稿缺少 `relations` 时补空集合，不自动改绑既有任务。
示例族仅在明确选择示例时增量创建。只读审查、自动检查与浏览器范围见[关系视图验证](task-relations-ui-verification.md)。

关系评审固定必要任务的准确完成身份，区分参考依赖与必要前置，并在当前导航中按起点保留画布。
同范围更正产物撤回受影响的验收依据，新范围工作保留此前履约；不同内部步骤的同名稿分别进入评审。
这些规则属于模拟适配和呈现，不构成 Core 协议或真实执行能力。

## 本地任务与流程配置

设置 → 任务与流程进入共享维护页。类型可自定义名称、图标、顺序、推荐和启停；模板支持草稿、步骤编辑、
固定版本预览、复制和启停。新任务明确选用准确版本，新版或停用不改写已采用快照。
更换流程预览影响并记录原因，旧未完成必要工作保留为任务验收条件；经核对的旧产物克隆为任务级材料。
可选工作完成或有理由地跳过，步骤接受不完成 Task；Agent 产物覆盖由用户确认，来源保持不变。
历史材料保留，并按流程上下文区分身份。

模拟配置规则在 `src/mock/configuration.ts`，类型化呈现端口和页面在 `src/workbench`；TS 源码导入供已有 Node
模拟测试使用，独立构建仍输出标准 ESM。配置与任务仍是浏览器 mock 草稿，不代表 Core 存储、真实派发或跨壳同步。
本轮测试、浏览器证据与边界见[配置交互验证](workflow-configuration-ui-verification.md)。
