### 确认并修复的两项问题

1. 流程更换后的历史只看 `accepted`，会把跳过显示成已确认，并隐藏理由。
   `TaskDetailPage.jsx` 改为按历史实例和步骤匹配跳过决定，显示理由；失效跳过另标示，兼容没有记录的旧历史。
2. 范围编辑器把条件拼为多行字符串、再按文本找第一个 ID，不能无损保留条件身份。
   连续更换相似流程形成同文条件后，保存会产生重复 ID；多行步骤目标延续为条件后，无修改保存也会拆项并意外作废范围证据。
   `TaskFlowDialogs.tsx` 改为独立条目编辑、按 ID 更新/删除，保留内部换行；实际提交通过 `toScopeCriteria` 保留身份。

先运行 4 项有效失败回归，分别缺失跳过状态/理由和只有一个扁平条件字段；均是断言失败，非环境错误。
修复后定向 47 项通过；另补停用类型/模板且发布后续版本并重载后，旧任务仍可按原版本完成评审的集成回归。
条件保存链路也检查无修改保存后的 criteria、scopeRevision、scopeHistory、accepted、docs 完全保留。
只读审查者回读修复后未发现新增确定缺陷；该意见不替代下述主代理测试和浏览器验证。
