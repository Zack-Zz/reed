# 本地运行、数据与升级要求

[English](local-runtime.md) | [简体中文](local-runtime.zh-CN.md)

状态：设计要求，尚未实现，未创建以下数据路径或系统服务。
从此前方案改用 Rust Core 不改变这些约束。

## 两步安装

1. 用户级安装经核验的目标 OS／架构 Core 制品，包含管理／引导入口和迁移内容。
   普通使用不要求全局安装 Rust/Node。Desktop 可选，不拥有 Core 安装，也不提供
   Core 必需的运行文件。
2. 从所需宿主的原生市场安装 Reed 适配插件，完成该宿主的信任／启用后，
   发现或调用登记的 Core 启动入口，协商 profile／协议并连接。
   缺 Core 时说明安装方式，不静默安装运行时或转为打开浏览器。

准确命令、包名、安装器和平台支持尚未发布。Core、Desktop、插件与数据的安装生命周期
彼此独立。插件可固定携带最小启动器／stdio 代理，但不携带数据库或第二个 Core。
必须验证整个启动链在空格／非 ASCII 路径、全新 GUI 登录、无终端 PATH 继承时可用。
云效 CLI、可选 Agent 引擎分别检查依赖／版本，缺少连接器依赖不能阻塞本地任务。

## 单写者与发现

默认 stable profile 在各壳之间共享。并发客户端先连接，操作系统用户／profile 所有权锁
只允许一个服务启动，且覆盖整个服务运行与恢复期。
发现信息在私有目录发布端点、服务代际、协议能力与 schema 事实。
PID 文件、心跳或端口可连均不足以证明所有权。
不兼容客户端进入诊断，不新建数据库或竞争服务。

另一把控制锁保护升级／激活元数据，不替代运行期写入锁。
旧启动器同样必须遵守维护和显式停止状态，不能自行选择全局 `latest` 程序。

## 存储与访问边界

| 平台 | 计划 profile 根目录 |
| --- | --- |
| macOS | `~/Library/Application Support/Reed/profiles/<profile-id>/` |
| Windows | `%LOCALAPPDATA%/Reed/profiles/<profile-id>/` |
| Linux | `${XDG_DATA_HOME:-~/.local/share}/Reed/profiles/<profile-id>/` |

profile 管理 SQLite 结构化数据、不可变产物版本、分段日志、恢复状态和备份。
IPC／锁位于用户私有运行目录；连接器凭据放系统安全存储，其命名独立于 Desktop 包和
Core 安装版本。开发使用显式隔离的模拟 profile，默认不连接用户 stable profile。

只有 Core 打开业务数据库。短事务原子保存状态修订、持久事件、幂等回执和同步 outbox
意图，外部调用在提交后执行。文件先临时写入、校验和原子落位再建立索引，
恢复时识别未完成登记。大产物／日志分页读取，不全量加载文件。
长期事件订阅不能持续持有 SQLite 读事务阻塞 checkpoint。
备份使用 SQLite 一致性备份和固定产物清单，不只复制活跃 WAL 数据库文件；
不自动清理未决证据、用户源码或活跃工作区。

首版信任边界是当前 OS 用户，不宣称抵御同用户下可任意运行的恶意代码。
私有 IPC 仍需要端点权限、可信注册及 profile／代际／能力校验。
网页自报 host/session/cwd 或 localhost 来源不能自我授权。
长期凭据不进入 React、URL、提示词、命令参数或日志。
凭据存储锁定／拒绝时明确诊断，不回退明文或要求打开 Desktop。
不宣称 SQLite／普通产物已经实现静态加密。

外部同步向配置来源发送选择的字段／评论；Agent 引擎可能把提供的上下文发送给自己的
远程服务。本地 M1–M8 不部署云任务数据库；未来可选的个人多设备复制/团队预留见[复制专题](replication.md)，不是首版运行依赖。
备份导出／恢复需要明确操作；迁移到另一台机器时重新确认路径、会话权限和工作区归属，
不自动接管运行中的工作。

## 生命周期

| 事件 | 必须发生的结果 |
| --- | --- |
| 未安装 Desktop，首次使用插件 | 经核验的引导入口启动并连接 Core，无 Reed Desktop 及其专属 WebView 依赖 |
| 四端同时连接 | 一个写入者，读取按主体／真实范围去重，写入按规范外部对象跨连接串行；只在需要时增加薄客户端代理 |
| 关闭窗口／退出 Desktop | 释放当前客户端订阅和桌面进程，不停止 Core／Bridge，不取消已接纳工作 |
| 宿主／客户端崩溃 | 标记观测失联，保留任务、证据、未决同步和执行归属 |
| 活动客户端租约已结束，且无自有工作、后台同步或其他明确驻留原因 | 默认按需模式等待 60 秒，再于 5 秒内退出 |
| 开启后台同步或受管理执行 | 保留明确的活动原因，不把隐藏窗口当成原因 |
| 显式停止后台 | 持久化停止意图、协调活动工作，启动器／重启规则不得静默撤销 |

登录启动与后台驻留是两个选项。按需模式不得无条件 KeepAlive／restart-always。
异常重启必须有界退避并检查维护／停止意图。
请求取消、确认进程停止和流程验收分别记录。
每个支持 OS 分别验证，不能只凭 detached 启动认定生命周期通过。

## 独立升级

不可变程序制品可共享，每个 profile 单独激活兼容版本。
Core、Desktop、插件、共享 UI、协议、schema 和宿主版本分别记录。
只有 Core 管理入口迁移数据；Tauri updater 只更新壳，插件只更新自身。

| 步骤 | 必须持久保证的边界 |
| --- | --- |
| Stage | 核验新制品及兼容性，记录哈希、目标和旧版，不改变激活版本 |
| Maintenance | 取得控制锁，记录 profile 维护状态，所有启动／重启入口遵守 |
| Drain | 停止新派发／写入，收敛已有工作；受管理 Attempt 未核清时推迟升级，不清除或重发远端 unknown |
| Backup/stop | 冻结全部业务／事件写入，刷盘已确认状态及最终游标，生成一致备份／清单，停止旧 Core 并释放写入锁 |
| Migrate | 只有目标迁移器取得所有权，核对实际 schema／迁移记录，事务迁移，保持禁写 |
| Activate | schema、恢复、投影和协议健康检查后原子激活 profile 版本，再开放访问并重新协商代际 |
| Recover | 任一步崩溃后核对维护记录、实际 schema 与进程所有权；矛盾时保持禁写 |

schema 已变化或新版已接受业务写入时，不自动恢复旧备份或启动旧程序；保留诊断，
前向修复或通过单独授权的恢复操作处理。
仍被 profile、进程或恢复记录引用的制品不能回收，包括 Windows 占用的二进制。
卸载 Desktop 或单个插件保留 Core 和数据；移除 Core 前处置其自有工作和启动注册。
永久删除数据／凭据是独立明确操作。以上是要求，不是当前安装器的实际行为。

## 补充运行规范

活动租约发放／续期／释放、准入交错、unverifiable 及回收规则见[生命周期与资源](lifecycle-and-resources.md)。认证后先查已有回执，再对新接纳请求检查业务前置，见[操作与恢复](operations-and-recovery.md)。旧备份恢复先保留原记录，默认暂停自动派发与 outbox，重新核对外部效果；证据缺口不能用缺少回执解释为未执行。

## 保存回执、持久化等级与有界存储

SQLite 继续是任务/验收/关系/操作/同步意图及事务事件的业务权威。
应用层依赖用例级窄事务端口，不暴露 connection、通用逐表 CRUD 或向下转型取驱动。
首版直接查询当前表即可；只有真实需求才引入可重建的搜索/统计异步投影，
投影失败不能重新启动 Agent、回写来源或重做验收。

业务保存回执必须等待所选 SQLite 提交边界完成；文件证据还需内容校验、可靠落位和
索引提交，临时文件或登记失败不能显示成有效验收材料。
文件与 SQLite 不构成一个原子事务，恢复分别处理孤立文件、登记中断和内容缺失/变化。

首版必需保证是 Core 进程崩溃后可恢复；断电持久性是单独定义和验证的等级，
不能从 COMMIT、flush 或 rename 名称推导。M2/M4 固定 SQLite 日志/同步策略、
文件与目录同步、适用文件系统及失败处理。部署若要求断电持久性，
该配置与故障证据未成立前不能宣称满足或交付该等级。
正向保存回执不早于承诺边界，错误可见可恢复；接纳操作仍不证明其外部效果完成。

分页同时限制页数、源字节、解码记录和输出，单条巨大数据也有限制。
先准备有界输入再进入短写事务，不占 writer 等网络/文件流；后续索引重建有检查点，
仍以已确认业务事实为准。多客户端一致性见[协议/客户端](protocol-and-clients.md)，验收 RF24。

M3 在同一 runtime 的隔离 profile 内验证 SQLite/迁移/私有 IPC 持久化底座，
M4 增加业务 schema 和合法任务读写，才验业务 ready；不为探针另建服务或第二数据库权威。
旧备份恢复还需按[操作恢复 §6.5](operations-and-recovery.md#65-旧备份恢复后的缺失回执)
改变接纳命名空间，防已执行但备份缺失的请求在新连接中重传成新操作；
普通重启/升级不随意轮换该边界，已知旧操作仍核查。

## 可选复制与设备身份

个人云复制开启时仍由本机 Core 独占本机 SQLite，云库另有服务写入者；
两台设备不共享数据库文件/锁。profile 与逻辑数据集/空间分开，
设备身份/认证不随数据备份或云副本复制，新设备重新注册/授权。
默认不创建账号、不探测云服务；未上传变更可持久保留，不成为永久驻留理由。
云不可达不阻止本地保存/既有执行，涉及共享协调的新动作按[复制专题](replication.md)受限；
解绑/停止复制不撤销已发动作，也不解除未决归属约束。
