# 应用协议与共享客户端

状态：2026-10-29 正式目标设计。仅 CoreHealth 诊断 DTO 与类型生成检查已有骨架；
本文业务认证、兼容、补读、背压及交互回复均待实现和验收。

## 契约权威与边界

应用用例在 reed-core 定义业务命令、查询及不变量；reed-protocol 定义 wire DTO、
错误、握手、事件和兼容规则，不导出数据库行或内部管理器。runtime 完成装配和转换，
传输不进入领域。先在三个 crate 内按模块组织，不新增服务或常驻 supervisor。

Rust 协议定义是通信类型单一权威，生成 TypeScript，不手工维护两份同义定义。
当前 ts-rs 只实现诊断导出，不能据此声称业务运行校验、JSON Schema 或完整 SDK 已建立。
明确缺省/缺失/null、未知枚举、数值精度、路径/时间表示、长度和大小限制；
需要 schema/校验器时追溯同一版本定义，并补充类型无法表达的约束。
结构反序列化、认证、授权、业务版本与证据检查分别成立，生成物对齐不能替代它们。

不预设 JSON-RPC 或 MCP。私有 IPC 与可选配对 HTTP 共享应用语义。
握手核验服务/调用者、profile、代际与协议范围，再协商稳定/实验能力。
能力声明不产生权限，也不证明宿主支持。破坏性变化明确拒绝，未知有副作用动作不猜测执行；
新增可选字段和未知结果值有兼容规则，固定新旧组合实测，不仅比较生成文件。

## 身份与结果

| 身份 | 责任 |
| --- | --- |
| 传输请求 ID | 当前连接的请求/响应关联，重连可变，不是业务去重键 |
| 稳定 requestId | 既定意图 ID，携带原接纳命名空间；profile/稳定主体内去重，重传不变；不是 serviceEpoch |
| operationId / invocationId | 持久接纳记录 / 一次真实效果调用，见操作恢复规范 |
| Task / StageRun / AgentAttempt | 任务、固定输入阶段轮次、一次执行，不按 RPC 或页面挂载新建 |
| serviceEpoch / 绑定代际 | 区分服务和宿主实例；失效不证明旧执行已停止 |
| recordRevision / 事件游标 | 并发写条件 / 已提交事件位置，不互换或改用客户端时钟 |

错误区分传输、协议/输入、认证/授权、版本/业务冲突、外部拒绝、效果未知、恢复/维护受限；
各自给出允许动作，客户端不统一自动重试。接纳、本地提交、宿主接纳、开始、终态、
验收、完成决定和远端确认分别呈现。旧回执查询先于新操作可变条件检查，
见[操作恢复](operations-and-recovery.md)，不因恢复响应再次产生效果。

## 一致快照与事件补读

1. 同一一致读取边界取得授权投影与已提交事件水位 C；当前表与事件仍在同一 SQLite
   事务提交。C 不是某条 Task 的 recordRevision。
2. 从 C 之后订阅，服务从持久事件补读并衔接实时入口，或提供等价的原子订阅屏障。
   查询后、注册前提交的更新不能漏掉。
3. 事件有稳定去重身份和单调位置；允许重传，客户端去重且不以旧修订覆盖新投影。
   通知驱动刷新，不代替业务权威，不回放命令重建数据。
4. 游标绑定 profile、查询/订阅范围、过滤/排序与必要版本；排序有稳定 tie-breaker。
   每次读取仍授权，游标不是凭据。范围变化、过期、截断或缺口明确要求重新取快照/水位，
   不静默跳至最新。持续变化分页若无一致快照，说明去重和可能遗漏语义。
5. 换代后先重新握手，有效持久游标可补读，epoch 改变不清历史。
   断开释放订阅，不持 SQLite 读事务等下一事件。

首版用现有事务事件表与普通查询，不建设事件溯源、消息总线或异步 CQRS。
事件保留与回执去重保留分别定义；能重取投影不意味着能重做旧效果。

## 有界流与客户端

控制响应、操作结果、交互请求与可裁剪日志分别调度，慢日志不堵控制响应。
限制队列项数、总字节、单条解码后大小、在途请求及生产任务数量；
仅用有界 channel 却无限创建等待任务不算有界。
业务通知超限时保留持久事实，明确补读/重同步，不能静默丢关键结果。
交互送达失败保持待处理/超时，不自动批准；日志尾随和历史缓存有界，截断可见可补读，
源读取也有界，不先全量读 1 GiB 再分页。卸载视图只释放客户端资源。

packages/client 负责握手、可注入传输、类型调用、错误、订阅/去重/重连和资源释放；
不导入宿主/Tauri SDK，不开数据库，不决定流程或重派未知效果。壳注入 transport/ShellBridge。
不可达、不兼容、停止/维护只进入诊断，不内嵌第二 Core、不另建 profile 或强迫打开 Desktop。

## 原目标回复与权限

HostAdapter 在事件进入时捕获原连接、请求实例、Attempt/目标、代际、有效期及授权主体，
不按界面当前选中会话路由。断线/回复失败先核查，不能在新连接盲重发旧请求 ID。
Core 有权管理的交互可多端展示，但一次决定经持久条件更新接纳，其他窗口收到已处理状态；
内存一次性句柄不能代替跨窗口/重启仲裁，决定被接纳也不等于已送达或执行成功。

原生审批仍由宿主拥有；无公开回复能力时导航原宿主，不复制为任意壳可批准的弹窗。
本契约不要求 MVP 建通用审批引擎；独立 AgentExecutor 的完整交互留后续 P8。
模型“通过”、已读或执行授权不构成 Reed 阶段验收。

## 验收

RF21 负责依赖/输入/兼容，RF22 负责快照/游标/背压，RF23 负责原目标回复，
RF24 负责持久化/投影。统一见[故障验收](../engineering/failure-acceptance.md)，资源只引用 RSC。

## Core 到宿主的控制通路

Rust runtime 不导入 ai-code 的 JS HostAdapter 实现。core 定义不含宿主 SDK 的控制端口，
protocol 定义有版本的受限命令/回执，runtime 经已认证的适配器控制连接发送。
插件受信端注册 profile、宿主/适配器实例代际、已验收动作及准确会话绑定；
页面仅发起意图或呈现，不承担唯一的执行/回执路由。

只向对应在线且获授权的适配器派发；命令复用 operationId/invocationId、Attempt、
SessionBinding、目标/输入及代际，适配端再次核对范围/目标。确认接收不等于原生提交/执行。
当前代际内去重交付；连接中断、换代或回执未知时不由重连/事件补读自动重发控制命令，
先核查原执行。插件不因此维护业务数据库或第二 outbox。

仅支持页面内调用、预填/导航或无可靠回控的宿主，按该能力声明限制；
Tauri 发起该原生动作时不能静默改走 SDK/CLI。M2 验双向命令/反馈，M6/M8 留真实证据。
页面关闭只释放视图；后台适配若无法继续可靠观测，保留未决记录并明确失联，
不能伪造结束。独立 AgentExecutor 仍是另一路径，不与这条原生回控合并。

## 筛选移出与访问范围变化

事件更新按投影成员变化处理：记录修改后移出状态/Connector/搜索筛选，
必须能使旧列表项移除或使该范围失效重取，不能只投递“修改后仍匹配”的事件。
解除关系、归档和删除也需相同语义。消息不暴露当前调用者无权读取的字段；
权限撤销先使相应订阅/缓存失效，不借旧游标继续展示为当前可见数据。
RF22 覆盖移入/移出/撤权，复用现有快照与事件机制。

## 未来跨设备复制协议

本机应用 API、UI 事件游标和请求命名空间不直接成为云端复制协议。
未来 reed-protocol 内独立 replication 命名空间携带数据集/空间、设备/副本、
稳定 mutation 身份、共享基线版本、来源与兼容语义；本地 requestId/revision、
接纳命名空间及 serverCursor 各自保持作用域。

本机 client 仍连接本机 Core，由 runtime 的可选复制适配对接云服务；
同一配对/IPC Token 不用作公网账号认证。服务器认证/空间成员检查独立于本机同 UID 信任，
不能把有本机访问权理解为拥有云空间权限。
复制变更入账使用无副作用导入路径，不能把变更重新解释为本机 API 命令/宿主控制。
详细契约与阶段边界见[复制专题](replication.md)，未在本轮生成任何云 DTO。
