# 可选云复制：个人多设备与团队协作预留

日期：2026-10-29。状态：已确认的设计预留，尚未实现。首个本地 MVP 仍按 M1–M8；
先个人多设备，再团队协作。本文是复制专题权威，方向见 ADR-0002，实施与验收分别
见[计划](../engineering/implementation-plan.zh-CN.md)和[RF](../engineering/failure-acceptance.md)。
本轮只修改 docs，不创建服务目录、Cargo 清单、数据库、账号或网络连接。

## 1. 产品范围与运行方式

本地任务无需账号或云服务，每台设备的 UI/四端插件始终连接本机 Core；
同 OS 用户/profile 一个本机写入者，不因云同步变成多进程共享 SQLite。
个人复制显式选择数据集、服务地址、账号和共享范围后启用，可手动、使用时或显式后台同步。
默认关闭，无云探测/登录依赖；云不可达不阻塞本地保存、查阅或已接纳执行。
Core 空闲退出策略仍成立，待上传记录本身不强制常驻。

云端保存被接受的共享版本、复制回执/变更和选定附件，协调冲突；
不接管本机数据库、文件系统、Git、宿主会话或进程。
收到副本只导入授权事实，不重放启动、验收、云效回写等业务命令。
复制、第三方 ProviderConnector 同步、HostAdapter 控制、AgentExecutor 分别管理。

## 2. 服务端工程结构与构建归属

下图是未来演进结构，不是当前实际目录。只预留责任，云阶段才创建：

```text
reed/
├── crates/
│   ├── reed-core/                 # 现有：可复用纯领域规则/应用端口
│   ├── reed-protocol/
│   │   └── src/
│   │       ├── local/             # 未来按需组织本机协议
│   │       └── replication/       # 未来：版本化复制 DTO
│   └── reed-runtime/
│       └── src/
│           ├── storage/           # 未来：本机 SQLite/文件适配
│           ├── connectors/        # 未来：云效等第三方来源
│           └── replication/       # 未来：本机上传/拉取/冲突适配
├── services/
│   └── reed-server/               # 未来：独立 Rust 云服务工程
│       ├── Cargo.toml             # 独立 Cargo workspace
│       ├── Cargo.lock
│       └── src/                   # 账号/空间、复制接纳、共享存储/附件
├── apps/                          # 现有：Web / 可选 Tauri
└── packages/                      # 现有：client / ui
```

reed-server 与 Core 同仓维护但单独构建、部署、签名/镜像及升级。
未来创建时明确排除在本地 root workspace 外，并独立管理锁/数据库迁移，
避免云端存储/鉴权依赖进入 Core-only 构建。可以依赖纯 reed-core 和 reed-protocol，
不依赖 reed-runtime、Tauri 或宿主 SDK。云库与本地 SQLite 是两个存储适配，
不将本地驱动替换为远程连接，也不把本机管理 API 直接公开到互联网。

云协议放 reed-protocol 的独立命名空间，与本机 IPC 分别版本协商/授权；
本机复制适配由 runtime 装配，UI 仍用本机 client。共享复制逻辑有实际复用需要时
才提取新 crate；不提前增加通用同步平台、CRDT、全事件溯源或调度器。
ai-code 继续只发行四端薄插件；服务端不进插件包，不由 Tauri updater 或插件市场部署。

## 3. 身份、版本与权威

| 身份/事实 | 约定 |
| --- | --- |
| 本机 profile | 安装、运行锁、凭据和本机事务隔离，不是跨设备数据集身份 |
| datasetId / SyncSpace | 本地逻辑数据集有稳定身份；开通复制时显式绑定云空间。首个版本一个数据集绑定一个空间，不按同名 profile/项目合并 |
| deviceId / replicaId | 设备安装及其数据副本身份；新设备重新注册，不复制旧设备控制身份 |
| Task/StageRun/Artifact/关系 ID | 创建时即可跨设备唯一，如 UUID；接入云不重编号，范围/模板版本的显示序号不承担全局排序 |
| mutationId / baseSharedVersion | 一次白名单变更及编辑基线；网络重传保持变更 ID/内容，不以本地 RPC ID 代替 |
| local revision / 共享版本 / serverCursor | 本机并发条件 / 云端接纳版本 / 复制流位置，各有作用域，不直接比较或复用本机事件游标 |
| actor / 成员权限 | 云端从认证和空间成员关系核验，不相信客户端自报的账号、设备或批准标记 |

SQLite 是本机提交与私有操作的权威，云端共享版本决定什么已被接纳为该空间的共享当前状态。
离线修改可本地保存并完成本地判定，但显示“待复制/待共享接纳/冲突”，
不能因此声称其他设备已看到、共享当前轮次已切换或外部效果已确认。
复制历史 Acceptance/CompletionDecision 与接纳当前有效指针分开；不删改本地曾经发生的决定。

首次接入先预览清单、选择数据和固定所属设备，再上传并建立快照/游标；
加入已有空间时处理已有本地变更，不用整库覆盖另一端。共享方向、保留版本和解绑结果可见。
备份恢复或副本克隆保留对象/变更身份，但重新核验设备/副本代际与同步检查点；
丢失本地回执时先查云端 mutation 回执，不重造 ID 将同一变更再执行。

## 4. 共享数据白名单与设备本地边界

| 类别 | 个人复制范围 | 留在设备或需要重新确认 |
| --- | --- | --- |
| Task/模板/范围/关系 | 稳定业务内容、不可变版本、来源与决定 | 当前共享指针按版本接纳；不复制私有权限能力 |
| Acceptance/完成/交付记录 | 原决定、准确输入/产物/代码版本、作者设备及适用性 | 不将 A 的验收当作 B 新代码的验收，不伪造云端重新执行验证 |
| 文档/报告/附件 | 元数据默认随选择的数据集，正文/附件按明确选项上传，内容版本/哈希独立于路径 | 本机绝对路径、安全目录授权及未选定内容不自动上传 |
| 会话/Attempt | 必要引用、原生身份命名空间、所属设备、观察状态/时间 | 活动绑定、回复句柄、控制能力、完整聊天/原始工具日志默认不复制 |
| 仓库/分支/代码 | 逻辑关联、提交/内容版本及观察来源 | clone、git common dir、worktree、脏文件与进程不搬运；代码通过明确 Git/内容交付另行获取 |
| Connector/来源 | 逻辑连接/来源身份、选定映射及同步状态摘要 | Token、安全存储引用、CLI 本机 profile/路径/环境、可消费 outbox 和控制授权不复制 |
| 私有操作/资源 | 必要的未决影响摘要和所属设备可共享供核查 | 本机请求回执、派发/清理队列、锁、PID、租约和执行器实例不变成另一端可执行记录 |

区分“本机未下载”“来源设备离线/无权限”“内容确认缺失/损坏”。
B 无 A 的文件路径不推翻 A 的历史验收；B 接受新成果仍须核对自己实际采用的内容与代码。
附件上传/删除、云端留存及可读主体在启用时说明，不因复制一个链接遍历本机目录。
密钥、控制凭据与完整原生聊天默认排除，也不藏在通用事件 payload 中上传。
白名单约束结构/字段，不承诺检测业务正文中的全部秘密；所选正文/附件可能含敏感内容，启用时须可预览并明确选择。

## 5. 变更交付与恢复

本地业务事务与白名单变更采集原子关联，可复用现有事件/事务机制，但定义独立复制变更集；
本地 MVP 只保留可扩展结构，不实现网络 worker 或长期 change-log 保留服务。
本机 UI 通知、复制变更和云效副作用队列的含义/游标/回执分别管理。

未来复制流程：

1. 启用时在一致边界建立初始快照水位和之后的白名单变更采集，上传期间的新编辑也能补齐；Core 提交业务事实及稳定变更身份/基线，离线保留，不伪装已上传。
2. 上传按账号/空间/副本验证版本、权限、输入与大小；同 mutationId 同内容返回原结果，
   异内容拒绝。云端业务变更、接纳回执及可补读记录原子入账后才确认。
3. 接纳检查当前共享基线及可核验领域约束，冲突返回双方内容和依据，不靠最后时间覆盖。
   服务端不声称已运行设备上的测试或拥有其宿主权限。
4. 拉取使用一致快照/水位、补读、去重、删除墓碑和有界批次；落地及 checkpoint 原子关联。
   Core 经明确导入路径更新事实，不调用会产生新副作用的原业务命令。
5. 日志压缩/游标过期要求完整重同步，并保留未上传变更供重基/处置。
   不能恢复已被删除的数据、重放历史决定或丢掉未决效果来“修复同步”。

接收远端事实不得重新产出同一 mutation 回传形成环。来源/actor/device/provenance 可追溯，
复制确认、某端已拉取、附件已下载与云效写入成功分别展示。某设备已拉取只在其明确确认 checkpoint 后显示，离线时保留最后确认时间，不由服务接纳推导所有副本已更新。
旧备份恢复的本机请求命名空间按操作恢复规则处理；它不等于 mutationId 或 serverCursor。
已经提交的 mutation ID 不因重连/恢复改变；本机缺失不是云端未接纳或外部效果未发生的证明。
云库恢复/换代造成回执或游标缺口时，先暂停不安全接纳/共享动作、保留已知确认并对账；不能用旧快照重启消费者。云端确认的持久化/备份恢复与留存保证到 C1 单独冻结，不继承本机备份保证。

## 6. 冲突规则与业务约束

| 交错 | 决策 |
| --- | --- |
| 两端改不同普通字段 | 基于共同版本做语义明确的合并；列表/成员/状态不通用拼接 |
| 同字段两端编辑 | 保留 B/本地/云端值，显式选择形成新变更，不用设备时钟 LWW |
| 两端改范围/迁移模板/切当前轮次 | 保留两个决定，当前指针条件更新，只能接纳一个有效当前结果；冲突另行选择/重判 |
| 验收与输入/代码更新交错 | 保留原接受，当前适用性重判；不合成“双方通过”或移植到新代码 |
| 删除/解除与离线编辑交错 | 墓碑/基线识别冲突，不能通过晚到快照自动复活 |
| 离线重复导入同一来源 | 不以外部对象匹配就合并 Task/执行；显式解决主导/主回写，保持来源唯一责任 |
| 旧设备/旧副本恢复后补传 | 核对版本/游标/变更回执；旧本地表不能覆盖已接纳的新共享状态 |

同一 Task 只有一个当前主轮次、单一主回写/主导、必要依赖无环等约束在共享接纳时再次检查。
离线本地成立不证明共享约束已成立。尚未共享接纳或有冲突的决定，不能成为跨设备
自动派发、云效关闭或转移执行所有权的依据。

## 7. 执行设备、云效写入与显式交接

C1 先支持数据共享，不开放共享任务的新原生阶段派发或共享关联来源的新写入，手动按钮和规则触发都适用；这些新动作须等待对应 C2 能力验收。既有执行的准确答复/收敛、核查、受支持的停止及非共享任务不受此禁令影响，仍须原目标和授权有效；不开放任意跨设备远程命令。
受管理原生执行记录明确所属设备；其他设备只查看或准备，不因复制 StageRun 就新派发。
在所属设备继续已接纳的 Attempt 不要求云持续在线，结果仍归原输入/代码版本；
C2 新增共享执行通过核验当前依据/所属设备的受控路径，未验证保持准备/受限，
不把本机完整能力直接宣称为跨设备完整能力。

云效回写按“空间 + 规范外部对象”显式指定唯一执行设备，凭据仍由其本机安全存储管理。
其他设备可以修改可共享数据，但不消费复制来的 outbox，不因 Token 相同另开一个消费者。
复制接纳本身不触发来源回写；若需要把远端修改变成外部动作，使用另行授权的新意图及
受控派发路径，不能回放历史状态。个人数据复制阶段 C1 对新共享原生执行/来源写入统一禁用，不能借手动独立外部编辑入口绕过；
已有本地自动化在加入共享范围时须明确停用或等待 C2 的启用验收；非共享任务仍按原本地规则。
切换共享模式先暂停新共享派发/写入，预览现有待发/在途/unknown及所属设备；未发暂停重判，已发保留核查，不借接入复制清空未决影响。C1 只声明数据能力，不宣称已交付可发起新执行的完整云工作台。

C2 开放前须验证共享版本接纳与派发占用的先后、稳定意图去重、所属设备核验及“效果可能发生”
边界；云端已接纳不等于实际执行成功。仅先拉取再发送不能消除间隙竞争，
共享依据/占用无法确认时保持待处理，不以本地过期缓存启动新共享副作用。
该在线约束只适用于需要共享协调的新动作，不阻止本地保存、纯本地任务及既有执行收敛。

交接先由旧设备停止新派发、汇总未决影响/回执并处置在途调用，再明确释放与接纳新归属。
旧设备不可达、停止不明或存在 unknown 时保留阻塞，不靠 TTL、心跳失联、云锁过期抢主。
人工风险接受仍是独立决定，不能伪造终态或撤销旧调用；无法保证时不开放自动交接。
本地恢复/云端恢复后重新核对当前归属，旧绑定不因数据库回退复活。

固定所属设备只约束已登记空间/通路的 Reed 操作；其他空间、用户终端及直接云效操作仍为
外部并发。云效无条件写/幂等能力的限制不因云端协调消失，不能承诺外部 exactly-once。
暂停云复制、解绑或退出账号不清除旧执行/来源 unknown，不自动给其他设备派发权。

## 8. 账号、空间与团队后续

个人账号可以拥有多个空间，首个版本每个数据集显式选一个；账号只在开通复制时需要。
云端账号令牌与本机 IPC、云效 Token、Agent 账号分别授权/保存。
默认仅空间所有者和已注册设备可访问选定数据；服务端逐请求检查身份/空间，
跨空间 ID/游标和客户端自报 deviceId/actor 均不授予访问。
传输保护、云存储/备份访问、附件授权、删除/留存和密钥生命周期须在 C1 冻结与验证；
目前不声称已实现静态或端到端加密。端到端加密若采用，另评审对服务端语义校验的影响。

团队沿用 SyncSpace，再增加成员、角色和共享策略，不把个人全部数据自动纳入团队。
云端角色允许编辑共享数据不等于某设备宿主执行授权，执行设备仍自行确认能力及范围。
成员撤销后拒绝后续云写/读取；离线缓存不能承诺立即远程擦除，重新连接需撤销相应能力、
更新可见范围并处理未上传变更，不静默用旧权限发布。
SSO/计费/复杂审批/远程 Worker 不属于本次预留实现。

## 9. 实施与验证边界

M1/M3/M4/M8 只承担已列明的结构/身份/事务边界预留，本地首版不依赖账号、网络或服务部署。
后续 C1 个人复制、C2 共享动作、C3 团队按[实施计划](../engineering/implementation-plan.zh-CN.md)
独立推进，不以完成 P8 多 Agent 反向集成为前提。
RF27–RF34 为云阶段待执行场景，不能加入当前 M8 的必需通过项；
本地 RSC01–RSC10 数值不变，云启用后的网络/队列/附件/服务端成本另建负载与预算再验收。
