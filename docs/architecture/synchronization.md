# 连接器与双向同步

状态：2026-10-29 汇总后的现行设计约束，尚未实现相关业务机制。

本文细化已有连接器/outbox；工程边界见[总览](overview.zh-CN.md)，取舍见[统一采用矩阵](../references/mechanism-adoption.md)。

## 9. 云效连接器与同步责任

### 9.1 配置、身份和能力

Core 拥有 Connector 配置、凭据访问、CLI 调用和同步队列；插件只提供配置、检测与状态映射界面。中心版与 Region 版分别配置接入点/区域和 CLI profile，多个连接独立保存；发现本机配置只生成可编辑草稿，经用户确认才建立连接，不自动同步全部组织/项目。

连接检测先证明 CLI 程序及版本、接入点、认证主体和可访问范围，再选择组织/项目与映射。能否仅凭 Token 枚举组织、查询合法状态流转、携带条件版本或指定幂等键，必须按所选 CLI/服务版本实际验证；不可用时仅补问必要字段，不把配置界面上的模拟发现当作已验证能力。凭据不返回普通页面和 Agent 上下文。

外部对象规范身份沿用原设计的 provider、已识别实例、组织和原始 workItem ID；区域/接入点用于识别实际实例，项目放在观察与映射上下文，不因项目归属变化另建仲裁键。Connector ID 表达访问路径与访问主体。两个连接访问同一规范对象时共用写入仲裁，不因换账号或改连接名称变成两个不同对象；无法证明是同一实例的别名时先人工确认，不能盲目合并。若后续来源证明 ID 只在项目内唯一，先修订该来源身份契约并承接原队列和未决影响，不静默换键。

### 9.2 CLI 的受控执行

使用固定、核验过的官方 CLI 可执行路径与结构化参数，显式选择连接配置；不依赖用户当前 shell/profile，不提供任意 shell 字符串接口。按已验证能力选择有界 JSON 输出或明确的解析契约，限制 stdout/stderr、并发、执行时长，错误和审计均脱敏。具体命令与参数留待 CLI 能力验证后固定，不在参考文创造未核实接口。

读调用可取消/重试，但取消不伪造“读取成功”。写调用开始后，CLI 超时、断网、杀掉本机进程、输出不可解析或中断等待，都可能对应远端已执行；只有可靠证据证明未调用/未产生效果时才认定可安全重试。CLI 退出码为零先说明程序报告成功，仍按该命令已验证的响应/回读契约记录远端确认程度。

### 9.3 持久同步意图

SyncIntent 保存明确来源：Task、范围及实际存在的流程轮次、具体业务决定（包括任务级/内部步骤 Acceptance、任务 CompletionDecision 或直接外部编辑决定）及其固定版本、主回写关系、字段级策略、映射版本、Connector/主体、规范目标、远端基线、本地期望、授权范围和顺序。真实派发形成不可变调用记录；核查证据追加保存。

本地业务决定与待发意图在同一事务提交；同步器从 Core 的持久 outbox 处理，不由任何页面直接读队列后回写。首版按规范外部对象串行化写入，即使来自不同 Connector、不同字段或不同窗口也共享一个顺序；读取可以去重并发。保守的对象级顺序避免状态/字段的跨字段约束被拆散，不预建复杂字段并行调度。

选取待发意图、核对前置条件与占用目标、记录调用开始在同一短事务中完成；占用与未知调用或未处置冲突关联并持久保存，不因内存队列重建、租约过期或重启被自动释放。首版无法证明独立的同对象写入均视为有依赖，后继改另一字段也不能绕过旧冲突；明确处置并采用新基线后再推进。该仲裁仅覆盖同一 profile 的 Reed 写入；其他 profile、机器和直接在云效修改的用户属于外部并发，仍受第 9.5 节的服务端能力边界约束。

| 同步处理状态 | 含义与下一步 |
| --- | --- |
| queued | 意图已持久保存、尚未调用；发送前重查依据、主导权、权限和基线 |
| dispatching | 已记录效果调用，可能触达远端；崩溃恢复不能直接重发 |
| awaiting_confirmation | 结果未知，持续核查或等待明确处置；相同对象后续写入受阻 |
| confirmed | 按适用契约确认该次写入结果；仍不代表本地任务已验收 |
| converged | 当前值与期望一致，只说明当前值；原调用仍可能需要核查，不能单凭此值释放未知调用阻塞 |
| conflict | 远端并发修改、流转条件或映射前置不成立，保留三方值和对象阻塞，明确处置后再检查后继意图 |
| rejected | 权限/业务/接口明确拒绝且已确认未产生该效果；修改条件后另建适用意图 |
| superseded/cancelled | 仅用于未派发且依据已失效/被替代的意图；已派发历史不改写 |

表中是处理阶段的参考描述，不要求将原架构的 pending/sending/unknown 等状态名称改成另一组枚举。尤其将“原调用是否收敛”和“当前远端值是否一致”保存为独立事实；展示 converged 不自动将 unknown 调用改为 confirmed。

### 9.4 派发前检查与映射

每次真实写入前，核对连接主体未变、意图未过期、主导关系仍适用、权限/授权仍有效、目标仍存在，以及所需远端版本和合法流转条件。仅自动规则意图要求对应字段的自动映射启用；人工外部编辑依据本次明确决定和远端基线校验，不能被它自己设置的自动映射暂停阻止。阶段接受触发的推进必须引用仍适用的 Acceptance/StageRun/输入与产物，接受更正或依据失效时重判未发项；所有规则自动写入外部完成/关闭类状态均必须另引用有效 CompletionDecision，不能用阶段 Acceptance 代替；目标含义不明不启用自动映射。同范围重开也会使旧关闭意图重新判断。

映射固定来源实例/项目/工作项类型与状态 ID、规则版本，不按中英文显示名相等就自动回写。需求阶段与外部状态并非天然一一对应；多对一、不可逆或缺失映射须可见。LLM 只能提出带依据的映射/流转候选，由用户或明确规则采纳；执行时由确定性规则检查。

本地接受可生成外部期望；远端变化先更新 ExternalItem 观察和候选，不直接接受本地阶段。直接修改云效字段使用单独的外部编辑用例，并按原模型暂停该字段自动映射；这个入口不能被规则借用来绕过 Reed 验收。

### 9.5 拉取与字段冲突

保存远端原始状态/修订、观察时间、连接主体和同步游标；具备可靠增量接口时使用增量，没有时采用有重叠窗口、去重和周期对账的有界扫描。游标只在对应批次持久提交后前进，失败不跳过。删除、不可见、权限丢失分别观察，不因一次缺失就删除本地任务。

同步前比较远端基线 B、当前远端 R 与本地期望 D：

| 条件 | 处理 |
| --- | --- |
| R = B 且 D 不同 | 具备有效依据时可尝试条件写入；无条件写能力时仍有读取到写入间的竞态 |
| R = D | 记录当前一致；不推导原请求已成功、迟到副作用已结束或任意后续写入已安全 |
| R、B、D 均不同 | 对相同字段标冲突，不静默用本地覆盖远端 |
| 本地/远端改动字段互不重叠 | 仅在字段语义及服务约束允许时生成合并候选；列表、负责人和状态等不盲目拼接 |
| 状态不存在或流转不合法 | 保留原意图，刷新能力/映射并明确处置；不凭 UI 名称跳状态 |

若所选云效接口没有经过验证的条件写能力，先读后写不能阻止其他云效用户在间隙修改。此类能力标明限制；高影响状态采用更保守的人工确认或受控写入策略并回读，但人工确认同样不提供服务端 CAS。不得宣称已经消除并发覆盖，不能通过换成 MCP 获得不存在的服务端保证。若项目/字段要求严格防覆盖且所选通路无法证明满足，必须禁用相应自动与直接写入；人工确认不能代替服务端 CAS。只有明确接受受控写入的残余风险时才开放该等级，并继续回读/核查，不能静默降级。业务政策沿用 [F16](../product/operation-flows.md)。

### 9.6 未知结果、过期意图与部分成功

已派发调用未知时，按原目标、主体和请求线索回查；有可靠请求记录/幂等契约则据此恢复。只看到远端值相同，无法证明原调用已终止；旧调用若可能迟到覆盖，继续阻塞同一对象，或在明确风险处置后才能推进后续意图。

保留以下三条处置路径：继续核查并暂停写入；解除绑定但保留未决记录；用户查看远端和待发差异后明确接受残余风险，形成独立处置决定。决定记录允许放行的对象、范围和队列位置；查询后续可发送项时必须考虑该决定，不能再次仅凭旧 unknown 将队列永久卡住。旧调用仍保留 unknown，放行不等于结果确认，后续漂移和迟到结果继续核对。

本地新期望可以保存，未发送的旧意图可被替代；已发送的旧意图必须保留并先核查。完成决定失效、同范围重开、映射升级或主导关系转移，都不能改变旧调用含义。旧写入后来成功时归原意图，不把当前 Task 改回完成；后续是否修正远端，基于新观察和新的明确决定，不自动“反向补偿”重开云效。

换 Token、改 Connector、解绑、删除配置或导入到另一台机器，均不清除未决对象阻塞。经核验属于同一主体的 Token 刷新可以保留连接、更新安全存储引用并继续核查，旧调用主体与历史不变。无法核验身份时先暂停写入；主体、组织或实例改变时新建连接，旧意图不自动迁移。凭据不可用时保留核查记录及安全诊断，不能静默换账号重发。

多字段、批次或多次 CLI 调用不假设原子性。保存每个已调用部分、确认字段及未决效果；成功部分不回滚成“从未发生”，失败部分不能无差别重放整个批次。当前值一致、人工接受风险和真实调用确认分别记录。

读取缓存按访问主体和可见范围隔离；共享规范对象的写仲裁不能成为跨账号共享私有可见数据的理由。写顺序只约束同一 profile 的 Reed 操作，不能冒充来源服务端 CAS。

## 逐操作能力表与开放条件

M2（原 P0）先固定 CLI/服务版本、中心/Region、实例/端点、认证主体/范围及读取/解析契约；
M7（原 P3）使用另获授权的测试账号核验写入。每项记录程序来源/哈希、命令契约、
响应样例/限制、证据日期、幂等作用域/保留期、条件版本含义、核查依据和副作用。
证据脱敏，不含 Token。下表目前全部待验证，不从 Demo 或 CLI 安装成功推导能力。

| 操作/问题 | 必须验证 | 不满足时的行为 |
| --- | --- | --- |
| 连接检测/主体 | 版本、目标实例、有效主体与可见范围；Token 刷新是否同主体 | 不能识别则暂停写，换主体新连接且不迁旧意图 |
| Token 发现组织 | 是否能枚举组织/显示名，中心/Region 差异与授权 | 仅补问必要组织字段，不假造发现结果 |
| 项目/工作项读取 | 字段/原始 ID 唯一范围、分页/增量/删除与不可见语义 | 有界重叠扫描/对账或限制范围；不可见不删 Task |
| 状态与字段候选 | 实际 ID、工作项类型、字段及可用转换/权限条件 | 候选不当合法动作；映射缺失/失效不自动回写 |
| 更新标题/描述等 | 条件更新是否真实执行、返回是否可关联、完整/部分结果 | 严格防覆盖模式禁写；其余受控模式须明确残余风险 |
| 状态转换/完成/重开 | 服务端条件、阶段接受/任务完成等准确依据、额外工作流/通知副作用及结果核查 | 不跳过 Reed 决定或服务规则；无所需保证禁用对应动作 |
| 创建工作项 | 幂等键/关联标记、作用域/保留期、可核查实际对象 | 未知后不盲重建；缺可靠保证时限制该功能并保留核查 |
| 评论/追加数据 | 追加副作用、幂等/关联查询及保留期 | 超时不盲重试，不用内容相等证明只执行一次 |
| 操作结果核查 | 能否证明该次结果/终结，还是只读到当前值 | 后者只记 converged，未知在途仍阻塞或显式风险处置 |
| 批次/多字段 | 调用原子性、逐项返回、限流与输出边界 | 逐项入账，不将部分成功整个重放 |

读取权限缓存按主体隔离，跨账号同对象的写顺序不共享私有字段，RF14/16 单独负向验证。
本地 Task 的来源可为 Reed；外部关系提供稳定 Connector ID、provider/实例/组织/原始 ID、
观察与同步状态。UI 可展示名称及来源导航，名称修改不改身份，解绑仍保留来源历史；
凭据不进入来源标记。一个任务多个来源的主导/主回写规则仍按既有模型检查。

官方 CLI 是首个受控 transport，Reed 不依赖 MCP 才能读取云效；
MCP 只调用已授权的 Core 用例。直接 OpenAPI 可作为今后同一 ProviderConnector 内的替代
通路，但需验证官方能力/认证/版本/错误和以上效果契约后单独选择，
不默认实现双 transport，更不在 CLI 能力缺口时静默切 API。
M2 发现的关键写能力缺失可以先限制为读取，不能为完成实现而降低严格写入要求。

## 配置快照与来源观察入账

发现的本机 CLI profile 只是配置草稿，不是不可变执行身份。真实调用固定已确认的
端点/区域/组织、主体、作用域及安全凭据引用版本，使用受控调用配置/参数，
不在身份检测后又依赖可被外部修改的默认 profile。Token 同主体刷新可选新凭据版本，
但不能改写旧调用主体；配置/主体不明先暂停，不在日志/数据库存凭据正文。RF14/15 验证。

并发拉取/回读在发起时记录目标、主体/可见范围代际及本地观察修订。
入账核对这些条件和已经观察到的较新事实；有可靠来源修订时按其已验证语义比较，
无可靠修订时用本地条件更新/读取协调防止“旧拉取晚到覆盖新回读”。
过期结果留为对应历史或丢弃呈现并安排有界重读，不覆盖新期望/较新观察；
不能靠远端或客户端墙钟判断因果，更不能据此宣称阻止来源外部并发。

共同同步基线 B 只随该字段明确采用/同步确认的业务事务推进，普通拉取不无条件改 B。
旧响应不恢复已经撤销的可见权限，也不把新账号缓存与旧账号合并。RF16/19 覆盖这些交错。

## 双向同步的最小成功闭环

M2 确定目标项目允许的字段和状态操作及保证等级；M7/M8 至少验证一次：
来源读取/幂等导入 → 本地明确编辑或有效阶段决定 → 合法真实回写并核查 →
远端再次修改 → 本地新观察/冲突处置。字段修改和映射状态推进的能力分别留证。
若必要写能力未提供、保证要求不满足或仅完成模拟，仍阻塞“双向同步”交付，
不能以只读降级或 RF“适用项”排除正向路径。创建/评论等追加副作用不是最小闭环，
未专门验收不启用。测试账号真实写入另需执行授权，本轮不进行。

## 与未来个人多设备复制的边界

本专题的 outbox/规范对象队列只保证本机 profile 内的第三方写入顺序；
它不自动扩张为多设备唯一消费者。未来[云复制](replication.md)同步选定业务事实，
不能将本机可消费 outbox、CLI 配置/凭据或旧调用复制到另一台机器重新执行。

共享空间中按规范外部对象显式指定写入设备，其他设备仅共享可见业务数据/状态摘要。
C1 仅复制数据，对新共享原生派发/共享关联来源写入同时限制手动与规则入口；C2 验共享依据、派发占用/去重及显式交接后再启用，
不能仅“先拉云端最新，再执行 CLI”就宣称没有竞争。
旧设备停派发且未决影响处置后才交接；不可达/unknown/TTL 到期不授予新设备写入权，
断开云同步也不清除该约束。来源无 CAS/幂等的界限继续成立。

## 统一任务模型下的状态映射

本地生命周期决定是映射依据；无流程任务的开始/提交评审可直接引用 Task 的准确决定和范围，
不要求补一个 StageRun。可选步骤规则只处理实际采用流程的对应事实，不能代替任务级评审/完成。
来源原始类型/状态附加展示，映射为本地候选动作后仍核对本地五状态及验收条件；
外部已完成/已归档不直接改变 Task。此处只校准既有责任边界，不宣称新的 CLI 能力或同步已实现。
