## 通用任务表达

Reed 中一件任务可以是需求、开发、测试、验证、文档等类型。类型说明这件工作是什么，生命周期说明它推进到哪里；
两者分别显示和筛选。需求任务在需求范围确认后即可完成（评审中为可选状态），不必等到开发结束；
文档或测试任务也不必经过需求、设计、开发、验证的完整链路。

| 维度 | 呈现内容 | 交互约束 |
| --- | --- | --- |
| 任务类型 | 需求、开发、测试、验证、文档等；未选显示「未分类」 | 不决定任务生命周期，不自动套用流程 |
| 任务生命周期 | 待办、处理中、评审中、已完成、已归档 | 所有类型共用；状态变更经过统一业务条件检查；完成记录 status 与 completedAt |
| 优先级 | P0、P1、P2、P3；未设置为空、不显示 | 只辅助展示与排序，不改变生命周期、完成判定或执行 |
| 责任人 | 本版默认「我」，可空；外部来源负责人后续由 connector 带入 | 责任人不等于执行者，详细执行事实单独表达 |
| 可选内部流程 | 显式选用的模板及其步骤、当前进度、确认结果 | 未选用时不展示空步骤；步骤只提供材料提示，不做硬校验，不阻止正常人工处理与完成 |
| Agent 执行 | 当前尝试、运行／等待／未知等执行事实及准确控制入口 | 与任务状态分开；Agent 结束或取消不自动完成或取消任务 |
| 来源状态 | 来源系统原始状态、观察时间及映射意图 | 作为附加信息，不覆盖本地生命周期或绕过本地验收 |
| 推进控制与提示 | 暂停、阻塞及其影响和恢复入口 | 不增加任务主状态；阻塞只影响相关操作 |

默认无内部流程；模板推荐不等于采用。仅显式采用后才有 WorkflowInstance／StageRun；无流程时执行、关联资源与完成记录直接归属 Task 的当前范围，不创建空阶段。
研发四阶段仅是一种显式选用的内部流程模板。内部步骤确认只推进所选流程，不能自动将整件任务置为评审中或已完成。
是否需要某个步骤、哪些成果必须验收，依据这件任务已确认的目标、范围和验收条件决定；不以固定阶段序号作为操作门槛。

## 任务关系视图（首版本地模拟）

> 2026-11-01 起：本节“产物复用/冻结依据”按关联资源与完成记录理解（见[领域模型 §16](domain-model.md#16-任务驱动模型收敛2026-11-01)）；关系证据引用资源版本，不引入独立产物实体。

任务详情提供“查看任务关系”，侧边栏也可进入；以选中任务为起点向右展开单父拆分树。
节点显示标题、类型、生命周期、流程选择、来源及会话／分支／文档数量；点击标题复用右侧详情抽屉。
收起、展开、切换起点、返回上级、缩放及背景平移只改变视角；关闭抽屉或从看板返回保留画布状态。
当前窗口按起点分别保留缩放和平移，进入子树后返回恢复父画布；完整详情也提供明确的“任务关系”返回入口。
这属于临时呈现状态，不是共享任务数据，也不保证重启后恢复。

节点“＋”支持新增子任务、关联已有任务和新增普通关联任务。新增任务仅标题必填，类型和项目可后补，
始终进入待办、默认无流程，不复制会话或工作区。拆分、普通关联和前置依赖明确区分；后两类用辅助列表与开关展示。
必要子交付或前置结果须另行确认对当前交付范围的影响，不允许借关联跳过任务级验收；普通关联不阻塞完成。
当前模拟页将未勾选必要性的前置关系标为“参考依赖 · 不阻塞验收”，不限制开始、提交评审或完成；
“必要前置 · 验收受限”检查提交评审和通过完成，可以先人工开始，不实现阶段开始调度。三类关系均不自动派发 Agent。

父任务完成前核对必要子任务的准确完成记录与范围版本；核对弹窗打开后子成果变更，须重新核对。
任务完成后沿用该次核对记录，不能静默换成子任务的新轮次；子任务完成也不会自动完成父任务。
同范围更正已接受资源会使相关旧完成依据待复核，父任务的完成记录提示复核；已完成/归档的父任务保留历史主状态并提示复核。
子任务明确采用新范围后的后续成果不自动撤销旧履约。资源版本由资源模块维护，任务只引用当时版本；跨步骤同名材料均按各自引用进入完成记录复核范围。

“查看示例”增量建立独立模拟任务族，不重置已保存任务；预览入口可使用 `?view=relations&example=1`。
页面与规则仍经共享 mock runtime 装配，不启动真实 Agent、Git 或来源操作；现行业务约束见[模型](domain-model.md#53-子任务与依赖)。

- 任务类型仍是可维护的分类（需求/开发/测试/验证/文档/未分类），用于表达工作性质，不决定生命周期。

- 研发流程由多个任务通过关联关系表达：任务详情按上游/下游/相关任务分组展示关联，当前状态即任务在看板中的位置。
- 旧缓存中的流程数据仅保留历史展示，不再参与完成判定；任务详情不提供流程入口。

## 任务详情与创建

所有类型共用以下详情结构，内容围绕当前任务的范围组织，不以研发阶段充当默认主导航。

| 区域 | 内容与操作 |
| --- | --- |
| 基本信息 | 标题、类型、生命周期、优先级、责任人、项目；显示创建时间与最近修改时间；未填写的组织信息可以后补 |
| 目标说明与验收条件 | 要完成什么、范围边界、如何判断完成；任务说明和参考资料独立于流程材料 |
| 处理记录 | 人工处理、Agent 执行、澄清、结果及后续处置；保留来源和时间，不伪造自动执行记录 |
| 关联资源与完成记录 | 关联文档、链接、文件、提交、会话及工作区；文档 v1 只读查看；完成记录自动保存完成时间与当时关联资源快照，不要求用户勾选依据 |
| 可选内部流程 | 仅在显式选用模板后展示；步骤提供目标、材料提示与确认提示，不做材料硬校验，不替代任务完成 |
| 活动与历史 | 展示操作历史摘要及完整列表；每次状态变更包含时间、前后状态与操作者 |

新建保持标题必填；类型可选或后补，未选显示「未分类」，按通用任务的目标、关联资源和验收条件处理；项目、优先级、责任人、仓库、资料也可后补。创建后停留待办，
明确「开始处理」后进入处理中，再选择人工处理或准备 Agent 执行；开始处理不自动启动 Agent。
无内部流程的任务也可以人工整理、关联资源、完成，不要求伪造阶段或 AgentAttempt。

启动 Agent 前按本次具体操作所需能力检查：需要代码访问或写入时检查准确仓库／工作区，需要宿主执行时检查准确会话、cwd 与控制能力；
缺失时展示对应准备入口。非代码任务不因没有仓库而一律禁止处理，不用 `stage >= 2` 之类固定阶段判断代替能力检查。

## 时间、优先级与责任人呈现

- 详情只展示创建时间与最近修改时间；每次状态变更的时间、前后状态与操作者写入活动历史，完整历史在活动区查看。
- 优先级使用 P0–P3 大写标签；未设置时不显示标签，不输出字符串“null”。样式只使用系统既有中性色阶：P0 最深、P3 最浅，不引入红/蓝强调色，也不与任务状态颜色混用；标签文字始终可见，不能只靠颜色区分。
- 列表、看板卡片与详情复用同一优先级标签；窄屏优先隐藏次要列，不挤压标题。
- 责任人本版默认显示「我」，可置为未指定；外部来源负责人由 connector 带入后显示平台来源标记，映射到本地联系人留待后续版本。
- 责任人不是执行者：Agent 会话、工作区和执行摘要作为独立区域展示，不塞进责任人字段。

## 生命周期与操作条件

所有任务类型共用待办、处理中、评审中、已完成、已归档五个状态，不强制逐级推进。
详情直接点击状态切换；最小任务可待办直接完成，不显示独立开始、提交评审或结果填写按钮。
评审中表达等待核对。完成时写入状态与完成时间，并自动保存当时关联资源快照；已配置的验收条件可在完成确认中核对，不要求提交或选择证据材料。必要关系和执行约束仍检查。

正文优先标题和内容，补充区域为选填验收条件、关系及评论。评论包含作者、时间及正文，完成和归档后可继续添加；
已有材料保留为关联资源，不转换成评论或伪造执行事实。最近活动和完整活动分别提供摘要及审计记录。

| 当前状态 | 可切换状态 | 条件 |
| --- | --- | --- |
| 待办/处理中/评审中 | 待办、处理中、评审中、已完成 | 当前状态不重复执行；人工完成即写入 completedAt，已填条件可核对，不要求证据材料；AI/CLI 完成须经标准 API 提交依据；重排期不允许未决执行 |
| 已完成 | 待办、处理中、评审中、已归档 | 重开保留历史完成记录；归档仅收纳已完成任务 |
| 已归档 | 已完成 | 恢复历史完成，其他操作先恢复 |

归档不能代替完成，也不能用来隐藏未完成、仍活动或待核查的执行。日常看板不增加归档列；
恢复归档不直接变为待办或处理中，不自动发起执行或来源回写。

完成或归档后，若完成时关联的资源实际变化，卡片/详情仍显示原生命周期，并列提示“完成依据待复核”；不能显示为当前有效通过或驱动自动关闭。仅重新定位并核实未变的原资源版本可记录适用性核查；需要补做、换版本或改范围则先恢复/重开，不因提示消失自动创建新完成记录或关闭意图。

评审中可以保存候选；采用影响被审范围、验收条件、类型规则、模板或成果的变更，先明确撤回到处理中并保留原提交。可提供“撤回并采用”组合确认，不能悄悄替换评审对象；完成/归档后采用这类变更则先按恢复/重开路径处理。

暂停是对后续推进的控制，阻塞说明缺失条件及受影响操作；两者均不改变任务主状态。
恢复或解除阻塞后重判当前条件，不直接发送旧准备。本轮不新增任务级取消／放弃终态，相关语义待单独确认；
不能用完成或归档冒充取消。取消某次 Agent 尝试仍是独立执行操作，取消请求不等于实际停止，结果须保留并核查。

## 任务完成与内部确认

任务完成由状态切换表达；人工完成不要求独立提交评审，也不要求选择或提交证据材料。评审中仍是可选的等待核对状态。
完成时系统自动保存 completedAt 与当前关联资源的快照（有则记，无则空），供之后查看与复核。AI/CLI 通过标准 API 完成时必须提交可核验依据；
步骤接受、阶段验收、Agent 输出、已读、评论、外部关闭或 PR 合成都不能代替任务完成。人工提交与 Agent 产出适用同样的资源和完成记录规则。

测试、验证任务的完成标准由目标和验收条件决定。若目标是执行测试并报告，真实的失败报告和必要执行证据可以是有效交付；
若目标明确要求测试全绿或达到质量门槛，失败结果则不能满足该条件。任务完成不改写测试实际结论，
失败、未运行与通过必须如实呈现，不因任务已完成而显示质量通过。所有必要任务验收条件须按已采纳约定满足；若要求执行指定计划，未运行或环境失败说明不能替代约定覆盖。减少承诺先做范围变更，不能在验收时静默忽略。

进入评审或完成时若关联资源不完整、版本已变或执行结果未知，展示准确原因和可恢复动作，保留草稿及历史；人工完成不因缺少材料被阻塞。
Agent 结束、用户已读、内部步骤确认、外部关闭或 PR 合并均不能代替任务完成；交付与上线事实仍单独记录。

## 来源与恢复状态

配置、检测、范围选择和映射逐步确认；云效中心版／Region、多连接都有独立来源标记。
Token 是否能枚举组织以核验后的 CLI 能力为准，不能凭模拟表单承诺。
第三方原始状态和映射意图附加在任务旁，来源关闭只产生可核查的观察或建议；
本地生命周期及其最终验收仍按同一规则判断，不能从外部状态直接跳到已完成或已归档。

「本地已保存」「远端当前一致」「原调用已确认」分别展示。
「重试执行」「继续核查」「重新同步当前期望」使用不同动作；客户端重新挂载不重新提交。
恢复、失联、冲突和残留资源提供具体下一步，不抢走用户当前视角。

## 未来个人多设备共享的呈现预留

开启复制是显式选择服务/账号、空间、数据与附件范围；默认不登录/上传。
本地已保存、待上传、云端已接纳、其他设备已拉取与共享冲突分别展示，与任务生命周期分别表达。
共享状态不改变五状态含义，也不绕过任务完成、归档及恢复条件。
任务/会话/分支标明来源设备，外机记录提供查看/准备或受限提示，不伪装能在本机直接控制。
附件未下载、设备离线、缺权限与内容丢失使用不同状态。
共享数据发生冲突时保留本地内容和双方依据，不用一次刷新覆盖草稿；
关闭复制不删除本地业务，也不伪造外部/执行终态。C1 的新共享原生派发/来源写入按钮与规则同样等待 C2 启用，不借手动入口绕过；已有执行的准确答复/核查/停止与非共享任务保持原规则。详见[复制设计](../architecture/replication.md)。

## 当前本地任务交互与实现边界

正式共享前端使用同一套 Web／Tauri 源码，模拟提供标题必填、类型与上下文后补、默认无流程及五状态流转。
通用详情围绕目标、验收条件、关联资源、处理记录与完成记录；人工完成不要求证据材料，完成记录自动保存完成时间与关联资源快照；归档恢复回已完成，重开保留历史。
可选流程只在明确采用时展示，步骤确认不自动完成任务；拖拽与按钮共用模拟规则。资料只登记引用，不读取真实文件。
当前 mock 仍保留旧的产物库/冻结评审实现，作为过渡；下一轮 UI 按本修订调整为时间显示、P0–P3、责任人（本人/未指定）、关联资源与完成记录、文档只读查看。
这些是前端模拟交互，完整 Core 规则、真实执行、同步和正式持久化仍待实现；
具体工程边界与验证方式见[前端开发](../engineering/frontend.zh-CN.md)。
