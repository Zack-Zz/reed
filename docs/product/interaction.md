## 通用任务表达

Reed 中一件任务可以是需求、开发、测试、验证、文档等类型。类型说明这件工作是什么，生命周期说明它推进到哪里；
两者分别显示和筛选。需求任务可以在需求范围与材料通过任务级评审后完成，不必等到开发结束；
文档或测试任务也不必经过需求、设计、开发、验证的完整链路。

| 维度 | 呈现内容 | 交互约束 |
| --- | --- | --- |
| 任务类型 | 需求、开发、测试、验证、文档等；未选显示「未分类」 | 不决定任务生命周期，不自动套用流程 |
| 任务生命周期 | 待办、处理中、评审中、已完成、已归档 | 所有类型共用；状态变更经过统一业务条件检查 |
| 可选内部流程 | 显式选用的模板及其步骤、当前进度、确认结果 | 未选用时不展示空步骤，不阻止正常人工处理与完成 |
| Agent 执行 | 当前尝试、运行／等待／未知等执行事实及准确控制入口 | 与任务状态分开；Agent 结束或取消不自动完成或取消任务 |
| 来源状态 | 来源系统原始状态、观察时间及映射意图 | 作为附加信息，不覆盖本地生命周期或绕过本地验收 |
| 推进控制与提示 | 暂停、阻塞及其影响和恢复入口 | 不增加任务主状态；阻塞只影响相关操作 |

默认无内部流程；模板推荐不等于采用。仅显式采用后才有 WorkflowInstance／StageRun；无流程时执行、产物与验收直接归属 Task 的当前范围，不创建空阶段。
研发四阶段仅是一种显式选用的内部流程模板。内部步骤确认只推进所选流程，不能自动将整件任务置为评审中或已完成。
是否需要某个步骤、哪些成果必须验收，依据这件任务已确认的目标、范围和验收条件决定；不以固定阶段序号作为操作门槛。

## 核心视图

| 视图 | 交互与约束 |
| --- | --- |
| 任务列表 | 标题、类型、生命周期、项目、责任／优先级、来源连接及 Agent 活动；可选流程进度另列；筛选无业务副作用 |
| 个人看板 | 日常保持待办／处理中／评审中／已完成四列；卡片显示类型与状态，可选流程仅作附加进度；已归档从独立筛选或历史入口查看，不增加第五列 |
| 任务详情 | 右侧抽屉保留看板筛选、滚动和选中上下文；通用内容按下节呈现，有内部流程才增加流程区域 |
| 会话与分支 | 任务、会话、分支视角读取同一关系投影；查看不 checkout、不发消息、不切执行目录 |
| 文档 | 可导航任务材料及确切版本、来源与适用性；路径存在不代表验收有效 |
| 执行准备 | 按具体操作检查所需仓库、工作区和宿主能力；需要隔离代码执行时先准备 worktree，再验证准确宿主会话 cwd；未交接不能标已隔离执行 |
| 连接器 | 先列来源类型，再选自定义／发现本机配置；发现只生成可编辑草稿，确认后才连接 |

拖拽只是发起与按钮一致的状态变更请求，由统一 Core 用例判断；不允许用列位置替代评审或完成决定。
条件不满足时卡片留原位，说明缺项和下一步。选中的详情、输入草稿与看板上下文保持不丢失。

## 任务关系视图（首版本地模拟）

任务详情提供“查看任务关系”，侧边栏也可进入；以选中任务为起点向右展开单父拆分树。
节点显示标题、类型、生命周期、流程选择、来源及会话／分支／文档数量；点击标题复用右侧详情抽屉。
收起、展开、切换起点、返回上级、缩放及背景平移只改变视角；关闭抽屉或从看板返回保留画布状态。
当前窗口按起点分别保留缩放和平移，进入子树后返回恢复父画布；完整详情也提供明确的“任务关系”返回入口。
这属于临时呈现状态，不是共享任务数据，也不保证重启后恢复。

节点“＋”支持新增子任务、关联已有任务和新增普通关联任务。新增任务仅标题必填，类型和项目可后补，
始终进入待办、默认无流程，不复制会话或工作区。拆分、普通关联和前置依赖明确区分；后两类用辅助列表与开关展示。
必要子交付或前置结果须另行确认对当前交付范围的影响，不允许借关联跳过任务级验收；普通关联不阻塞完成。
当前模拟页将未勾选必要性的前置关系标为“参考依赖 · 不阻塞验收”，不限制开始、提交评审或完成；
“必要前置 · 验收受限”检查提交评审和通过完成，可以先人工开始，不实现阶段开始调度。三类关系均不自动派发 Agent。

父任务提交确认展示并固定必要任务的准确完成记录与范围版本；确认弹窗打开后子成果变更，须重新核对。
评审一旦提交，后续完成沿用该次绑定，不能静默换成子任务的新轮次；子任务完成也不会自动完成父任务。
同范围更正已接受产物会使相关旧完成依据待复核，父任务的冻结评审被阻断；已完成/归档的父任务保留历史主状态并提示复核。
子任务明确采用新范围后的后续成果不自动撤销旧履约。产物以“任务内步骤＋标题”区分版本，跨步骤同名稿均进入冻结依据。

“查看示例”增量建立独立模拟任务族，不重置已保存任务；预览入口可使用 `?view=relations&example=1`。
页面与规则仍经共享 mock runtime 装配，不启动真实 Agent、Git 或来源操作；现行业务约束见[模型](domain-model.md#53-子任务与依赖)。

## 任务类型与流程模板维护（本地模拟）

左下设置提供“任务与流程”独立页面，以任务类型、流程模板两个页签维护；新建任务、看板和详情继续复用同一注册配置。
类型用于分类，支持名称、说明、图标、多模板推荐、排序和启停；未分类保留兜底。已被任务或历史引用的类型不可删除，停用不改写存量任务或评审快照。
类型与推荐模板多对多；一个任务当前采用一个可选流程。更换类型只改变推荐列表，不自动采用或更换流程。

模板编辑包括基本信息、稳定身份的顺序步骤、目标/处理说明、产物要求、人工检查要点、必要性、处理方式及代码工作区要求，
以及建议任务验收清单。草稿可保存，检查完整后本地“保存并启用新版本”；已发布版本只读，编辑形成后续版本，内置模板通过复制定制。
新版不升级旧任务；停用不撤销已采用快照。已发布或曾使用模板保留历史，仅从未使用、未发布的个人草稿可删除。
相同已发布内容没有编辑时不重复启用新版本。模板步骤使用共享下拉组件，页面离开与全局导航保护未保存输入。

新建仍仅标题必填，类型和流程可后补；用户选择类型后查看推荐与其他模板，预览步骤及准确版本，创建时明确采用，停留待办。
新建类型可在表单中完成；进入模板管理再返回保留新建草稿。停用选项不供新任务选取，失效的旧草稿选择明确提示重新选择。
模板建议验收项通过按钮加入目标编辑草稿，经用户保存后才作为当前任务的条件，不因选择模板自动确定业务目标。

已有任务更换、移除或采用新版流程先预览准确任务依据、旧必要工作、步骤接受与产物影响，并填写原因和确认。
本模拟实现将旧流程未完成必要步骤及要求延续为任务级验收条件；新流程不继承旧通过位，旧产物与决定进入历史，
明确核对的复用版本克隆为任务级材料，不按相同阶段数字用于新步骤。评审、完成、归档及旧执行的处置仍遵守原生命周期约束。
可选步骤完成或记录原因后跳过；内部接受不替代任务级评审。Agent 原始产物由用户对准确版本明确确认覆盖，保留宿主来源。
更换流程后的历史区分已确认、已跳过和未确认；跳过原因保留，失效记录明确标示。任务验收条件按独立条目编辑、添加与移除，保留各项身份和多行正文；同文但不同来源的延续条件不因文本相同而合并，无修改保存不生成范围变更。
产物标题和说明帮助用户核对交付，不用字符串匹配冒充语义验收；真实工作与实际结果仍由用户审阅确认。

当前配置与任务仍保存在显式 mock runtime 中，同一页面刷新可恢复；不是 Rust Core 存储或跨壳共享数据的实测。
Web/Tauri 共用组件、样式、配置呈现和模拟规则，不创建独立 Demo 工程。验证范围见[配置交互验证](../engineering/workflow-configuration-ui-verification.md)。

## 任务详情与创建

所有类型共用以下详情结构，内容围绕当前任务的范围组织，不以研发阶段充当默认主导航。

| 区域 | 内容与操作 |
| --- | --- |
| 基本信息 | 标题、类型、生命周期、项目及责任／优先级；未填写的组织信息可以后补 |
| 目标说明与验收条件 | 要完成什么、范围边界、如何判断完成、必要产物；任务说明和参考资料独立于流程产物 |
| 处理记录 | 人工处理、Agent 执行、澄清、结果及后续处置；保留来源和时间，不伪造自动执行记录 |
| 产物与评审 | 任务交付材料、确切版本、适用范围、任务级评审及最终验收结论；内部步骤确认另有归属 |
| 关联资源 | 资料、会话、分支和工作区及其关系；关联不赋予执行权限，不自动创建或切换资源 |
| 可选内部流程 | 仅在显式选用模板后展示；说明步骤目标、产物、确认和返工，不替代任务级评审 |

新建保持标题必填；类型可选或后补，未选显示「未分类」，按通用任务的目标、产物和验收条件处理；项目、仓库、资料也可后补。创建后停留待办，
明确「开始处理」后进入处理中，再选择人工处理或准备 Agent 执行；开始处理不自动启动 Agent。
无内部流程的任务也可以人工整理、提交产物、评审并完成，不要求伪造阶段或 AgentAttempt。

启动 Agent 前按本次具体操作所需能力检查：需要代码访问或写入时检查准确仓库／工作区，需要宿主执行时检查准确会话、cwd 与控制能力；
缺失时展示对应准备入口。非代码任务不因没有仓库而一律禁止处理，不用 `stage >= 2` 之类固定阶段判断代替能力检查。

## 生命周期与操作条件

所有任务类型统一采用「待办 → 处理中 → 评审中 → 已完成」，完成后可整理为已归档。
状态表达任务进度，执行活动、暂停、阻塞、来源状态和共享状态在旁边独立呈现。

| 当前状态 | 操作与目标状态 | 条件及保留内容 |
| --- | --- | --- |
| 待办 | 开始处理 → 处理中 | 明确开始；后续可人工处理或准备 Agent，不自动派发执行 |
| 待办 | 开始并提交 → 评审中 | 已有完整成果，明确组合意图并满足与处理中提交相同的条件，不要求启动 Agent |
| 处理中 | 退回待办 → 待办 | 无已知活动执行，且无待核查的未知执行；用于重新排期，保留处理记录、产物与关联资源 |
| 处理中 | 提交评审 → 评审中 | 明确整件任务的评审范围、当前验收条件及产物版本；必要工作已完成、所需产物可核查，相关写入执行已确知结束，不存在影响该版本判断的未知写入 |
| 评审中 | 要求修改／撤回评审 → 处理中 | 记录原因及原评审对象；再次提交时明确本次评审版本，不把旧结论套到新内容 |
| 评审中 | 最终任务验收通过 → 已完成 | 对整件任务的明确范围和产物版本形成完成决定；核对必要交付、已承诺的条件及必要子任务；所选流程的必要步骤不能有未处置项 |
| 已完成 | 重新打开 → 处理中 | 明确继续工作及适用范围，记录新一轮处理依据；无流程时不创建空阶段；保留原完成决定与证据，不将历史完成当作新工作的验收 |
| 已完成 | 归档 → 已归档 | 仅整理已完成任务，先核对妨碍成果/资源安全的未决执行；保留历史和依据适用性提示，不删除关联资源 |
| 已归档 | 恢复归档 → 已完成 | 恢复历史完成事实，保留完成依据待复核提示；如需继续工作，再显式重开到处理中 |

归档不能代替完成，也不能用来隐藏未完成、仍活动或待核查的执行。日常看板不增加归档列；
恢复归档不直接变为待办或处理中，不自动发起执行或来源回写。

完成或归档后，若原证据实际失效，卡片/详情仍显示原生命周期，并列提示“完成依据待复核”；不能显示为当前有效通过或驱动自动关闭。仅重新定位并核实未变的原准确依据可记录适用性核查；需要补做、换版本或改范围则先恢复/重开，不因提示消失自动创建新验收或关闭意图。

评审中可以保存候选；采用影响被审范围、验收条件、类型规则、模板或成果的变更，先明确撤回到处理中并保留原提交。可提供“撤回并采用”组合确认，不能悄悄替换评审对象；完成/归档后采用这类变更则先按恢复/重开路径处理。

暂停是对后续推进的控制，阻塞说明缺失条件及受影响操作；两者均不改变任务主状态。
恢复或解除阻塞后重判当前条件，不直接发送旧准备。本轮不新增任务级取消／放弃终态，相关语义待单独确认；
不能用完成或归档冒充取消。取消某次 Agent 尝试仍是独立执行操作，取消请求不等于实际停止，结果须保留并核查。

## 任务级评审与内部确认

任务级评审回答「这件任务在当前明确范围内是否已经完成」，绑定整件任务的验收条件、必要产物及确切版本。
没有内部流程时仍可提交和完成任务级评审；选用了内部流程时，步骤接受、阶段验收或 Agent 输出仅作为任务级判断的依据，
不自动提交整件任务评审，也不自动生成完成决定。内部已接受的材料和证据可直接复用，不强迫对同一材料多层重复审阅；
如提供步骤接受与任务验收的组合操作，须明示整件任务的评审范围、条件及结果，仍作出明确的任务级决定。必要实际工作已完成、仅待内部人工确认时可纳入同次评审，不要求重复审批；未做工作不能当作待确认提交。人工提交与 Agent 产物适用同样的版本和验收规则。

测试、验证任务的完成标准由目标和验收条件决定。若目标是执行测试并报告，真实的失败报告和必要执行证据可以是有效交付；
若目标明确要求测试全绿或达到质量门槛，失败结果则不能满足该条件。任务完成不改写测试实际结论，
失败、未运行与通过必须如实呈现，不因任务已完成而显示质量通过。所有必要任务验收条件须按已采纳约定满足；若要求执行指定计划，未运行或环境失败说明不能替代约定覆盖。减少承诺先做范围变更，不能在验收时静默忽略。

进入评审或完成时缺材料、版本已变或执行结果未知，展示准确原因和可恢复动作，保留草稿及历史。
Agent 结束、用户已读、内部步骤确认、外部关闭或 PR 合并均不能代替最终任务验收；交付与上线事实仍单独记录。

## 来源与恢复状态

配置、检测、范围选择和映射逐步确认；云效中心版／Region、多连接都有独立来源标记。
Token 是否能枚举组织以核验后的 CLI 能力为准，不能凭模拟表单承诺。
第三方原始状态和映射意图附加在任务旁，来源关闭只产生可核查的观察或建议；
本地生命周期及其最终验收仍按同一规则判断，不能从外部状态直接跳到已完成或已归档。

「本地已保存」「远端当前一致」「原调用已确认」分别展示。
「重试执行」「继续核查」「重新同步当前期望」使用不同动作；客户端重新挂载不重新提交。
恢复、失联、冲突和残留资源提供具体下一步，不抢走用户当前视角。

## 未来个人多设备共享的呈现预留

开启复制是显式选择服务/账号、空间、数据与附件范围；默认不登录/上传。
本地已保存、待上传、云端已接纳、其他设备已拉取与共享冲突分别展示，与任务生命周期分别表达。
共享状态不改变五状态含义，也不绕过任务级评审、完成、归档及恢复条件。
任务/会话/分支标明来源设备，外机记录提供查看/准备或受限提示，不伪装能在本机直接控制。
附件未下载、设备离线、缺权限与内容丢失使用不同状态。
共享数据发生冲突时保留本地内容和双方依据，不用一次刷新覆盖草稿；
关闭复制不删除本地业务，也不伪造外部/执行终态。C1 的新共享原生派发/来源写入按钮与规则同样等待 C2 启用，不借手动入口绕过；已有执行的准确答复/核查/停止与非共享任务保持原规则。详见[复制设计](../architecture/replication.md)。

## 当前本地任务交互与实现边界

正式共享前端使用同一套 Web／Tauri 源码，模拟提供标题必填、类型与上下文后补、默认无流程及五状态流转。
通用详情围绕目标、必要验收条件、产物版本、处理记录和关联资源；任务级评审固定依据，逐项明确接受后完成，归档恢复回已完成，重开保留原因与历史。
可选流程只在明确采用时展示，内部确认不自动完成任务；拖拽与按钮共用模拟规则。资料只登记引用，不读取真实文件。
这些是前端模拟交互，完整 Core 规则、真实执行、同步和正式持久化仍待实现；
具体工程边界与验证方式见[前端开发](../engineering/frontend.zh-CN.md)。
